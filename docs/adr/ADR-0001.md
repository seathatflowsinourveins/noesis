# ADR-0001: Clean Architecture Layers (`L0..L10`), Upstream-Only Native-First & AST Zero-Self-Invention

- **Status:** Accepted
- **Date:** 2026-11-25
- **Evidence Grade:** E4

## Context and Problem Statement

Quantitative repositories routinely accumulate duplicate engines, custom HTTP pollers, custom agent hooks, transitive banned dependencies (`yfinance`), non-OSI licensed tools, and brittle code-golfing to satisfy naive line-count gates. `tier0-sota-clean` requires a 100% standalone clean-room architecture anchored strictly to pinned OSI-compliant upstream winners across `L0..L10`, `SOTA_STARRED_AND_BEYOND_MANIFEST.json`, and native `.pre-commit-config.yaml` / `ast-grep` checks with zero self-invented runtime hooks.

## Decision Drivers

- **11-Layer Single-Winner Discipline (`L0..L10`):** Locked in `uv.lock` (`0` transitive `yfinance`), `upstream-map.toml`, and `SOTA_STARRED_AND_BEYOND_MANIFEST.json` with canonical GitHub slugs (`treeverse/dvc`, `stumpy-dev/stumpy`, `microsoft/PyRIT`, `superradcompany/microsandbox`).
- **SPDX OSI License Firewall (`spdx_license_firewall`):** Strictly excludes `BSL-1.1`, `ELv2`, and custom non-OSI tools (e.g., `treeverse/lakeFS`, `restatedev/restate`, `Arize-ai/phoenix`, `NX-AI/tirex`).
- **Mechanical Structural & Static Enforcement:** `ast-grep`, `ruff`, `ty`, `deptry`, `gitleaks`, and `z3-solver` formal SMT proofs, with zero custom runtime `"hooks"` blocks.
- **Standalone Portability:** All `46` vetted skills reside inside `.claude/skills/` with zero dependency on external legacy repositories.

## Considered Options

1. **Hard per-file LOC caps with custom runtime hooks and permissive transitive deps** — encourages code-golfing, leaks banned packages (`yfinance`), and risks non-OSI license drift.
2. **Full `L0..L10` OSI-vetted stack + AST structural gates (`ast-grep`) + native `.pre-commit-config.yaml` + `deptry` + `0` `yfinance` `uv.lock` + immutable `risk.py` SHA-256 + advisory LOC telemetry**.

## Decision Outcome

Adopt Option 2 across all 11 architecture layers:
- **`L0` Runtime & Lockfile:** `uv`, Python 3.13 (`0` transitive `yfinance`).
- **`L1` Data & PIT:** `Polars`, `DuckDB`, `Pandera`, `exchange_calendars`, `EdgarTools`, `FRED`, `treeverse/dvc`.
- **`L2` Signals & Drift:** `ml4t-engineer`, `River`, `Ruptures`, `stumpy-dev/stumpy`, `LightGBM`, `CatBoost`, `SHAP`.
- **`L3` Single-Engine Execution:** `NautilusTrader v2` + Rust `hftbacktest`.
- **`L4` Broker & Feeds:** `alpaca-py` (Paper-only).
- **`L5` Falsification:** `skfolio`, `ml4t-diagnostic`, `arch`, `statsmodels` (`0` transitive `yfinance` in `uv.lock`).
- **`L6` Observability & Docs:** `MLflow`, `Dagster`, `Optuna`, `Zensical`, `Prometheus`, `OpenTelemetry`.
- **`L7` Quality, AST & Formal Verification:** `ruff`, `ty`, `deptry`, `ast-grep`, `gitleaks`, `z3-solver`, `Hypothesis`, `pytest`, `pre-commit`, `trivy`, `syft`, `osv-scanner`, `shellcheck`, `zizmor`.
- **`L8` Agent Evals & Sandboxes:** `Inspect AI`, `DSPy`, `microsoft/PyRIT`, `superradcompany/microsandbox`, `harbor`, `promptfoo`, `skillevaluator`.
- **`L9` Multi-Runtime Harness & Memory:** `Orca`, `codebase-memory-mcp`, `XERJ`, `FastMCP`.
- **`L10` Institutional UI & Visual Analytics:** `finos-workspace`, `OpenBB`, `perspective`, `lightweight-charts`, `ag-grid`.

### Consequences

- **Positive:** 100% standalone OSI-compliant repository, zero transitive `yfinance`, zero shadow engines, zero custom runtime hooks, formal SMT risk guarantees.
- **Negative:** New external packages require OSI SPDX verification and `SOTA_STARRED_AND_BEYOND_MANIFEST.json` / `upstream-map.toml` approval before locking.
