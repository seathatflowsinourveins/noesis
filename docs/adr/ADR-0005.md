# ADR-0005: Formal Immutable Risk Kernel (`risk.py` Rule-612 `<= 2.00%`, `-1.50%` Fuse, `>= 10%` Reserve)

- **Status:** Accepted
- **Date:** 2026-11-25
- **Evidence Grade:** E4

## Context and Problem Statement

Floating-point rounding drift, unquantized sub-dollar ticks, unchecked intraday losses, or API rate exhaustion can breach maximum per-trade risk or prevent protective exits during market stress.

## Decision Drivers

- Exact `Decimal` arithmetic (`float()` forbidden) with Reg-NMS Rule-612 ticks (`$0.01 >= $1.00`, `$0.0001 < $1.00`).
- Conservative inward stop quantization so stop loss never exceeds `2.00%` (`MAX_STOP_LOSS_PCT`).
- Session-latched `-1.50%` daily drawdown circuit breaker and `>= 10%` protective exit API rate reserve.

## Considered Options

1. **Inline float stop calculations inside strategy code** — prone to rounding beyond `2.00%` and tick rejections.
2. **Standalone, SHA-256-immutable `src/tier0_sota/risk.py` (`361` LOC)** verified via property tests and AST guards.

## Decision Outcome

Adopt Option 2. `src/tier0_sota/risk.py` is preserved verbatim from the formally verified kernel (SHA-256 `ad8071dcd4196c4c529c02107114ebfdda6692bc9d7c220031f1b19ea3e4d847`, `361` LOC). All strategy, paper-farm, and TradingView modules delegate Rule-612 quantization (`quantize_rule_612`), capped stops (`compute_capped_stop_price`), risk sizing (`size_position_by_risk`), drawdown latching (`DailyDrawdownBreaker`), and exit rate budgets (`ProtectiveExitRateBudget`) directly to `risk.py`.

### Consequences

- **Positive:** Mathematically guaranteed `<= 2.00%` stop loss across sub-dollar and dollar regimes.
- **Negative:** Any modification to `risk.py` fails the repository SHA-256 verification gate unless explicitly re-ratified.
