# ADR-0018: Multi-Model Agentic Harness, OmniRoute Three-Tier Auth, Dual-Flywheel Compounding Self-Reflection & `L11..L15` Earned-Trigger Frontier Governance

- **Status:** Accepted
- **Date:** 2026-11-26
- **Evidence Grade:** E4
- **Sole Source of Truth:** SOTA upstream convergence per Core Trading Philosophy

## Context and Problem Statement

Operating a multi-model quantitative engineering harness across six developer runtimes (`Codex`, `Claude Code`, `Gemini CLI`, `OpenCode`, `Antigravity`, and `Orca`), Windows 11, WSL2 `Noesis-SOTA`, and public GitHub Actions introduces five recurring failure modes when left unmanaged:

1. **Instruction & MCP Drift Across Runtimes:** Per-runtime prompt duplication, custom shell wrappers, and divergent MCP configs cause inconsistent tool behavior and silent safety regressions.
2. **Auth Collisions & Rate-Limit Stalls:** Setting global provider API keys overrides native OAuth subscriptions in interactive CLIs, arbitrary `availableModels` caps block dynamic model routing, and single-account quota exhaustion stalls unattended multi-agent runs.
3. **Open-Loop Agent & Strategy Evolution:** Without deterministic evaluation harnesses and scheduled reflection loops, backtest findings, paper-farm telemetry, prompt/skill quality, and architectural decisions decay instead of compounding.
4. **Supply-Chain & Workflow Exposure:** Unpinned GitHub Actions, stale dependency locks, leaked home paths or credentials, and unaudited agent skills weaken security posture.
5. **Speculative Frontier Dependency Bloat:** Admitting emerging AI/quant repositories without empirical bottlenecks, SPDX OSI license verification, or measured benchmark lift floods `uv.lock` with unmaintained shelf-ware.

This ADR establishes the unified `L7..L9` multi-model agentic harness, `OmniRoute` three-tier authentication and routing policy, Dual-Flywheel compounding self-reflection loop, supply-chain gates, and earned-trigger `L11..L15` frontier governance anchored on SOTA upstream convergence per Core Trading Philosophy (`PHILOSOPHY_COMPOUNDING_MANIFEST.json`).

## Decision Drivers

- **Standards-Anchored Meta-Convergence:** Ground repository governance in neutral upstream standards — Linux Foundation Agentic AI Foundation (AAIF) `AGENTS.md` and `MCP` (`mcp==1.30.0`), MADR 4.0 living evolvable ADRs (`ADR-0001+`), PEP 735 `[dependency-groups]` (`uv.lock`), SPDX OSI license compliance, and Conventional Commits.
- **Strict Execution-Hot-Path Isolation:** Keep all LLMs, agent SDKs, prompt optimizers, and MCP tooling permanently off the synchronous `NautilusTrader v2` execution engine and immutable pure `Decimal` `src/tier0_sota/risk.py` kernel (mechanically enforced via `ast-grep` rule `no-llm-on-execution-hot-path`).
- **Three-Tier Auth & Zero-Downtime Routing:** Preserve native OAuth subscriptions for interactive CLIs with zero global API-key overrides, route local automations and routine CI through local-first `OmniRoute` (`http://127.0.0.1:20128`) with HTTP 429 auto-fallback, reserve banked `anthropic` and `openai` API keys strictly for high-quality SOTA runs (zero `GEMINI_API_KEY`), and automate Orca multi-account failover via official CLI commands.
- **Empirical Dual-Flywheel Compounding:** Continuously validate strategy parameters (`NautilusTrader v2` + Rust `hftbacktest` + `Optuna 5.1.0` + `MLflow 3.18.0`) alongside harness invariants and reflection quality (`Inspect AI 0.3.292` + `DSPy 3.5.0` + `Dagster 1.13.31` + `XERJ` + `Caddy` + `Orca` weekly Opus review).
- **Earned-Trigger `L11..L15` Admission:** Track frontier candidates (`SOTA_STARRED_AND_BEYOND_MANIFEST.json`) transparently with explicit promotion triggers, admitting new upstreams only upon empirical need, SPDX OSI clearance, measured lift, and a living MADR 4.0 record.

## Considered Options

1. **Per-runtime prompt copies, custom shell hooks, global API-key overrides, and speculative frontier installs** — causes CLI OAuth lockouts, fragile hook breakage, instruction drift across runtimes, unverified prompt regressions, and bloated dependency trees.
2. **Single-vendor model setup without local proxy failover, offline safety evals, or formal frontier promotion criteria** — vulnerable to single-provider rate limits and outages, lacks deterministic safety/skill regression tests, and cannot systematically adopt emerging `L11..L15` capabilities.
3. **Standards-Anchored Multi-Model Harness (`AAIF AGENTS.md` + `Orca` + `OmniRoute` Three-Tier Auth + `codebase-memory-mcp` + `XERJ` + `46` SHA-locked skills) + Dual-Flywheel Self-Reflection (`Optuna`/`MLflow`/`Inspect AI`/`DSPy`/`Dagster`/`Orca`) + `L7..L9` Supply-Chain Gates + Earned-Trigger `L11..L15` Frontier Governance**.

## Decision Outcome

Adopt **Option 3** as the governing architecture for `L7..L9` agentic operations and `L11..L15` frontier evolution, extending [ADR-0001](ADR-0001.md), [ADR-0002](ADR-0002.md), [ADR-0012](ADR-0012.md), and [ADR-0017](ADR-0017.md).
