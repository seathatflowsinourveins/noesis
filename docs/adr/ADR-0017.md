# ADR-0017: Native Workstation Hosting, Disk-Z WSL2 Noesis-SOTA, 15-Portal Upstream Engine Stack & Automated Post-Restart Recovery

## Context and Problem Statement

The Tier-0 engine must run 24/5 on one stationary workstation and survive any Windows, WSL2, or Antigravity restart without manual repair. [ADR-0011](ADR-0011.md) (Superseded) documented only 13 loopback portals and predated the verified 15-portal stack, the OTel health endpoint (`:13133`), OmniRoute (`:20128`), the 8-asset active Dagster compounding reflection job with its weekday schedule, live OTLP/Prometheus telemetry emission, the logon keep-up task, and one-command `just resume` recovery. Alongside [ADR-0021](ADR-0021.md) (which supersedes the `L10` UI half), this ADR **supersedes [ADR-0011](ADR-0011.md) (Superseded)** as the authoritative native hosting, observability, and recovery specification.

## Decision Drivers

- Host every engine surface natively on Disk-Z (`Z:\noesis`, `Z:\sota-data`, `Z:\workspaces`, `Z:\WSL`) inside the default WSL2 distro `Noesis-SOTA` with `systemd=true`, so a cold boot reconstitutes the stack declaratively.
- Govern resources at three layers: global WSL2 caps (`.wslconfig` memory, swap on Disk-Z, `autoMemoryReclaim=dropcache`, `vmIdleTimeout=-1`), systemd units for host-bound services, and per-container `cpus` / `mem_limit` in `docker/compose.sota.yml`.
- Keep every portal strictly on loopback (`127.0.0.1`), zero live broker ports (`:4001`, `:7496`, `:8798`, `:8796`), `paper_only=True`, and `live_execution_enabled=False`.
- Serve the upstream projects' own interfaces as shipped. Official images run `otel-collector-contrib`, `prometheus`, `alertmanager`, `grafana` and `caddy`; MLflow, Optuna Dashboard, Dagster, Inspect and Zensical run their own CLIs (`mlflow server`, `optuna-dashboard`, `dagster api` / `dagster-webserver` / `dagster-daemon run`, `inspect view`, `zensical serve`) on the local `tier0-sota-research` image, although MLflow and Optuna Dashboard also publish official images; XERJ runs on its local image; the profile-gated `finos-workspace` and `aideml-sandbox` services run inline `python -c` mount and version probes, not upstream interfaces. No inline-Python telemetry or HTTP shim; verified OSI licenses only.
- Recover automatically at logon and verify mechanically with one command (`just resume` / `just preflight`), writing an auditable manifest.

## Considered Options

1. **Docker Desktop on Windows with ad-hoc manual start-up and hand-written dashboards** — lacks native systemd, breaks declarative reconcile, and violates Zero Self-Invention.
2. **Native WSL2 `Noesis-SOTA` + systemd units + Docker Compose + official Caddy/OTel/Prometheus/Grafana, with a Windows logon keep-up task and `just resume` preflight** — declarative, loopback-only, mechanically verified.
3. **Option 2 plus un-triggered `L14` frontier services (`Temporal`, `Loki`/`Tempo`/`Pyroscope`, `Langfuse`, `marimo`)** — premature before measured triggers fire; deferred to earned-trigger governance (while `Alertmanager` has now crossed into profile-gated `--profile alerting` admission per [ADR-0028](ADR-0028.md)).

## Decision Outcome

Adopt **Option 2** (superseding [ADR-0011](ADR-0011.md) (Superseded) for hosting/observability while delegating `L10` institutional UI contracts to [ADR-0021](ADR-0021.md)):

- **Dashboards rule (owner decision `2026-11-27`, "Upstream UIs + config"):** the interfaces the upstream projects ship are used as they are; configuration written here for upstream platforms stays (Grafana dashboard JSON for the harness's own metrics, Prometheus rules and scrape targets, Alertmanager routes, the collector config, the Caddyfile); every figure, page or table renderer written here is replaced by the upstream's own function; the four Pine scripts and three TradingView documents are the TradingView lane's named exception; the end state is no HTML, CSS, JS, template or figure code written in this repository outside that exception. Grafana keeps its stock Explore and Metrics Drilldown for ad-hoc queries; report pages follow [ADR-0016](ADR-0016.md) and the `L10` contracts [ADR-0021](ADR-0021.md), which lists what is still open.
- **Host layout:** Default WSL2 distro `Noesis-SOTA` (`/etc/wsl.conf`: `systemd=true`, `automount` disabled, no Windows PATH injection). - **Four systemd units + one timer** (verified `active=4/4` by `wsl_systemd_services`): `tier0-duckdb-ui` (DuckDB SQL UI `:4213`, read-only), `tier0-openbb-backend` (OpenBB/FINOS backend `:6900`), `tier0-ollama-docker-bridge`, `tier0-openbb-docker-bridge`, plus `tier0-wsl-cache-reclaim.timer`.
- **Docker Compose (`docker/compose.sota.yml`, project `docker`):** 12 default-profile services (`docker compose config --services`, `2026-11-27`) with explicit `cpus` / `mem_limit`: `mlflow` (`:5000`), `optuna-dashboard` (`:8080`), `dagster-webserver` (`:3000`), `dagster-daemon`, `dagster-code-server`, `inspect-view` (`:7575`), `zensical` (`:8010`), `telemetry-exporter` (`otel/opentelemetry-collector-contrib:0.166.0`, `:9464`/`:4317`/`:4318`/`:13133`, `otelcol_lines=80`, receiving live `opentelemetry-exporter-otlp` + `prometheus_client` metrics from `src/tier0_sota/live/performance.py` per [ADR-0019](ADR-0019.md)), `prometheus` (`prom/prometheus:v3.16.0`, `:9090`, 30d retention, `15` alert rules), `grafana` (`grafana/grafana:13.3.2`, `:3001`; the Metrics Drilldown app it preinstalls is pinned with `GF_PLUGINS_PREINSTALL=grafana-metricsdrilldown-app@3.2.0`), `xerj` (`:9200`), and `tearsheets` (`caddy:2.11.9-alpine` fixing CVE-2026-27588..27590, `network_mode: host`, `bind 127.0.0.1`, serving the whole `/mnt/z/sota-data/manifests` tree with `file_server browse`, including `:8793/tearsheets/`, static **Allure Report 3** at `/test-reports/allure/` + `/test-reports/junit.xml`, and `:4213 -> 127.0.0.1:4214` Origin-normalising DuckDB UI reverse proxy preserving HTTP `401` CSRF guard). ## Consequences

- **Positive:** Reconstitutes the 15-portal WSL2 `Noesis-SOTA` + Docker Compose stack and OmniRoute router deterministically after host restarts via `just resume` and `13/13` always-on preflight gates, eliminates `:6900` port collision between `finos-workspace` and `tier0-openbb-backend`, wires live OTLP/Prometheus Paper Farm telemetry, and executes all 8 active Dagster compounding assets.
- **Negative:** Splits runtime state between Disk-Z mounts (`/mnt/z/sota-data`) and WSL2 ext4 (`~/tier0-sota-state`), requiring operators to maintain Compose/systemd parity via `just resume`.

## Pros and Cons of the Options

### Option 1: Docker Desktop + manual startup + custom dashboards

- Good, because initial Windows setup uses a GUI installer.
- Bad, because it lacks native `systemd` reconciliation, adds Hyper-V overhead, and invites custom web shims.

### Option 2: Native WSL2 `Noesis-SOTA` + systemd + Docker Compose + `just resume`

- Good, because all 15 loopback portals and OmniRoute recover automatically at logon with explicit resource caps and mechanical preflight receipts.
- Bad, because operators must manage WSL2 ext4 state vs Disk-Z mounts cleanly via `just docker-ps` / `just resume`.

### Option 3: Option 2 + immediate `L14` frontier services

- Good, because it would pre-stage distributed tracing and durable workflows.
- Bad, because it adds unmeasured RAM/maintenance cost before any operational trigger fires.

### Self-Invention Lesson Learned & Mechanical Upstream Gate

- **Lesson Learned:** Hosting facts drifted when maintained in prose (`13` vs `15` portals; `11` vs `13` gates). The machine-written preflight manifest and `docker/compose.sota.yml` are now the single source of runtime truth, and inline-Python telemetry/HTTP shims were permanently replaced by official `otel-collector-contrib` and `caddy`.
- **Mechanical Upstream Gates:** `just resume` / `just preflight`, `scripts/grand_reset/verify_grand_reset.ps1` (`hosted_portals_15`), `tests/test_grand_reset_kit.py`, `shellcheck` + `bash -n`, `rules/zero_self_invention.yml`, `trivy fs`, `gitleaks`, and `zensical build --clean --strict`.
