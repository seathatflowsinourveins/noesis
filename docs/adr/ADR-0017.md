# ADR-0017: Native Workstation Hosting, Disk-Z WSL2 Noesis-SOTA, 15-Portal Upstream Engine Stack & Automated Post-Restart Recovery

## Context and Problem Statement

The Tier-0 engine must run 24/5 on one stationary workstation and survive any Windows, WSL2, or Antigravity restart without manual repair. [ADR-0011](ADR-0011.md) (Superseded) documented only 13 loopback portals and predated the verified 15-portal stack, the OTel health endpoint (`:13133`), OmniRoute (`:20128`), the 5-asset Dagster reflection job with its weekday schedule, the logon keep-up task, and one-command `just resume` recovery. Alongside [ADR-0021](ADR-0021.md) (which supersedes the `L10` UI half), this ADR **supersedes [ADR-0011](ADR-0011.md) (Superseded)** as the authoritative native hosting, observability, and recovery specification.

## Decision Drivers

- Host every engine surface natively on Disk-Z (`Z:\noesis`, `Z:\sota-data`, `Z:\workspaces`, `Z:\WSL`) inside the default WSL2 distro `Noesis-SOTA` with `systemd=true`, so a cold boot reconstitutes the stack declaratively.
- Govern resources at three layers: global WSL2 caps (`.wslconfig` memory, swap on Disk-Z, `autoMemoryReclaim=dropcache`, `vmIdleTimeout=-1`), systemd units for host-bound services, and per-container `cpus` / `mem_limit` in `docker/compose.sota.yml`.
- Keep every portal strictly on loopback (`127.0.0.1`), zero live broker ports (`:4001`, `:7496`, `:8798`, `:8796`), `paper_only=True`, and `live_execution_enabled=False`.
- Serve only official upstream images and CLIs (zero inline-Python telemetry or HTTP shims) under verified OSI licenses.
- Recover automatically at logon and verify mechanically with one command (`just resume` / `just preflight`), writing an auditable manifest.

## Considered Options

1. **Docker Desktop on Windows with ad-hoc manual start-up and hand-written dashboards** — lacks native systemd, breaks declarative reconcile, and violates Zero Self-Invention.
2. **Native WSL2 `Noesis-SOTA` + systemd units + Docker Compose + official Caddy/OTel/Prometheus/Grafana, with a Windows logon keep-up task and `just resume` preflight** — declarative, loopback-only, mechanically verified.
3. **Option 2 plus immediate `L14` frontier services (`Temporal`, `Loki`/`Tempo`/`Pyroscope`, `Alertmanager`, `Langfuse`, `marimo`)** — premature before a measured trigger fires; deferred to earned-trigger governance.

## Decision Outcome

Adopt **Option 2** (superseding [ADR-0011](ADR-0011.md) (Superseded) for hosting/observability while delegating `L10` institutional UI contracts to [ADR-0021](ADR-0021.md)):

- **Host layout:** Default WSL2 distro `Noesis-SOTA` (`/etc/wsl.conf`: `systemd=true`, `automount` disabled, no Windows PATH injection). Windows `.wslconfig` caps VM memory (`80GB`), places swap/crash dumps/distro on Disk-Z, and uses `networkingMode=mirrored` (`free -g` reports ~78 GB total inside `Noesis-SOTA`).
- **Four systemd units + one timer** (verified `active=4/4` by `wsl_systemd_services`): `tier0-duckdb-ui` (DuckDB SQL UI `:4213`, read-only), `tier0-openbb-backend` (OpenBB/FINOS backend `:6900`), `tier0-ollama-docker-bridge`, `tier0-openbb-docker-bridge`, plus `tier0-wsl-cache-reclaim.timer`.
- **Docker Compose (`docker/compose.sota.yml`, project `docker`):** 11 default-profile services (`running=11/11`) with explicit `cpus` / `mem_limit`: `mlflow` (`:5000`), `optuna-dashboard` (`:8080`), `dagster-webserver` (`:3000`), `dagster-daemon`, `inspect-view` (`:7575`), `zensical` (`:8010`), `telemetry-exporter` (`otel/opentelemetry-collector-contrib:0.123.0`, `:9464`/`:4317`/`:4318`/`:13133`), `prometheus` (`prom/prometheus:v3.2.1`, `:9090`, 30d retention), `grafana` (`grafana/grafana:11.5.2`, `:3001`), `xerj` (`:9200`), and `tearsheets` (`caddy:2.9.1-alpine`, `caddy file-server` on `:8793`, read-only manifests mount). Profile `sandbox` adds network-less, read-only, `cap_drop: ALL` `aideml-sandbox`. Profile `portals` defines `finos-workspace` (`:1420`, `:8000`, and `:6900` in `docker/compose.sota.yml:377`) — **port `:6900` is mutually exclusive with host systemd `tier0-openbb-backend`**, so in the active systemd-hosted configuration FINOS runs on `:1420`/`:8000` while systemd `tier0-openbb-backend` owns `:6900` (never launch `--profile portals` concurrently with systemd `:6900` without disabling one binding). Containers run as `1000:1000`.
- **15 verified portals + parameterized Tailscale Serve access** (all host sockets strictly `127.0.0.1`; `local_portals_15: healthy=15/15`): XERJ `:9200`, Zensical `:8010`, MLflow `:5000`, Dagster `:3000`, Optuna Dashboard `:8080`, Inspect View `:7575`, Prometheus `:9090`, Grafana `:3001`, OTel metrics `:9464/metrics`, Caddy tearsheets `:8793`, FINOS Workspace `:1420`, FINOS API `:8000/health`, OpenBB backend `:6900`, DuckDB SQL UI `:4213`, and OTel health `:13133`. `docker/compose.sota.yml` parameterizes Host-header allowlists/origins on `:5000`, `:7575`, and `:8010` via `TIER0_TAILSCALE_HOST`, `TIER0_TAILSCALE_SHORT`, and `TIER0_TAILSCALE_IP` (defaulting to loopback) for peer workstation access over Tailscale Serve (`8/8` HTTP `200`/`302`). OmniRoute (`:20128/api/health`) is gated separately (`omniroute_local_router`).
- **Dagster (`tier0_sota.definitions`):** 5 assets (`prewall_pit_audit`, `risk_kernel_sha256_attestation`, `paper_farm_performance_snapshot`, `inspect_safety_and_philosophy_eval`, `compounding_self_reflection_snapshot`), `compounding_reflection_job`, and `daily_compounding_reflection_schedule` (`0 18 * * 1-5`, `America/New_York`). `docker/dagster.yaml` sets `QueuedRunCoordinator` (`max_concurrent_runs: 1`, `max_runtime_seconds: 1800`, `telemetry.enabled: false`).
- **Automated post-restart recovery:** Windows scheduled task `Noesis Orca Mesh Keep-Up` (logon + every 5 minutes, windowless) warms `Noesis-SOTA`, starts units/compose/OmniRoute, and refreshes the preflight manifest. `just resume` reconciles (`scripts/preflight_resume.{ps1,sh}`); `just preflight` is read-only.

## Consequences

- **Positive:** Reconstitutes the 15-portal WSL2 `Noesis-SOTA` + Docker Compose stack and OmniRoute router deterministically after host restarts via `just resume` and `13/13` always-on preflight gates.
- **Negative:** Splits runtime state between Disk-Z mounts (`/mnt/z/sota-data`) and WSL2 ext4 (`~/tier0-sota-state`), and requires respecting `:6900` mutual exclusivity between systemd `tier0-openbb-backend` and compose profile `portals`.

## Pros and Cons of the Options

### Option 1: Docker Desktop + manual startup + custom dashboards

- Good, because initial Windows setup uses a GUI installer.
- Bad, because it lacks native `systemd` reconciliation, adds Hyper-V overhead, and invites custom web shims.

### Option 2: Native WSL2 `Noesis-SOTA` + systemd + Docker Compose + `just resume`

- Good, because all 15 loopback portals and OmniRoute recover automatically at logon with explicit resource caps and mechanical preflight receipts.
- Bad, because operators must manage WSL2 ext4 state vs Disk-Z mounts cleanly via `just docker-ps` / `just resume`.

### Option 3: Option 2 + immediate `L14` frontier services

- Good, because it would pre-stage distributed tracing and durable workflows.
- Bad, because it adds unmeasured RAM/maintenance cost before any operational trigger fires.

### Self-Invention Lesson Learned & Mechanical Upstream Gate

- **Lesson Learned:** Hosting facts drifted when maintained in prose (`13` vs `15` portals; `11` vs `13` gates). The machine-written preflight manifest and `docker/compose.sota.yml` are now the single source of runtime truth, and inline-Python telemetry/HTTP shims were permanently replaced by official `otel-collector-contrib` and `caddy`.
- **Mechanical Upstream Gates:** `just resume` / `just preflight`, `scripts/grand_reset/verify_grand_reset.ps1` (`hosted_portals_15`), `tests/test_grand_reset_kit.py`, `shellcheck` + `bash -n`, `rules/zero_self_invention.yml`, `trivy fs`, `gitleaks`, and `zensical build --clean --strict`. Recovery tooling never issues host or VM shutdown/restart commands.
