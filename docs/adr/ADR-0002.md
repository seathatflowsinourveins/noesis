# ADR-0002: Dual-Flywheel Compounding Learning Harness (`XERJ`, `MLflow`, `DuckDB`, `Inspect AI`, `DSPy`)

- **Status:** Accepted
- **Date:** 2026-11-25
- **Evidence Grade:** E4

## Context and Problem Statement

Both engineering sessions and quantitative research trials risk repeating solved mistakes or losing empirical backtest/paper telemetry unless insights feed back automatically into a durable, queryable memory and offline red-team evaluation loop.

## Decision Drivers

- Separate synchronous execution hot paths (`NautilusTrader v2`, `risk.py`) from asynchronous LLM/RAG/eval tooling.
- Persist every research trial (`<= 2026-10-15`) and paper-farm run in structured experiment and ledger stores.
- Continuously gate agent safety, live-port refusal, zero-hook discipline, and `risk.py` integrity via deterministic offline `Inspect AI` evals (`evals/tier0_inspect_eval.py`).

## Considered Options

1. **Ad-hoc markdown logs and manual session summaries** — unsearchable and prone to drift.
2. **Dual-Flywheel Loop:** quantitative evidence ledger (`MLflow` + per-account `DuckDB`) paired with engineering memory/eval flywheel (`XERJ :9200` + `Inspect AI` `evals/tier0_inspect_eval.py` + `DSPy`).

## Decision Outcome

Adopt Option 2. Every falsification run logs parameters, costs, CPCV/DSR/SPA/HAC metrics, and git context to `MLflow` (`:5000`), while per-account paper execution telemetry lands in isolated `DuckDB` stores (`paper_lane_{pa1,pa2,pa3}.duckdb`). Engineering architecture lessons, failure post-mortems, and converged configurations are deduplicated into `XERJ` (`http://127.0.0.1:9200`) and gated offline via `evals/tier0_inspect_eval.py` (`inspect_ai` `Task`, `Sample`, `match`, `verify_inspect_safety_suite()`) and `DSPy` outside the execution hot path.

### Consequences

- **Positive:** Closed-loop empirical learning across both trading research and multi-agent safety evaluation.
- **Negative:** Requires running local Docker/WSL services (`MLflow`, `XERJ`) for full telemetry persistence while `evals/tier0_inspect_eval.py` runs 100% offline.
