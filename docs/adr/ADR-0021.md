# ADR-0021: Institutional Analytics UI, Real-Time 24/5 Trading Cockpit & Multimodal Quantitative Workbench (L10)

## Context and Problem Statement

Operating a 24/5 quantitative trading and research workstation across four compounding harness lanes (`sim-backtest`, `paper`, `half-auto-tv`, `live`) requires institutional-grade visual analytics: multi-lane paper equity and drawdown telemetry, real-time extreme-mover watchlists and staged order tickets, high-density streaming blotters, sub-second SQL inspection over `DuckDB` and pre-wall Parquet lakes, and backtest/attribution reports drawn by the upstream libraries' own report and plot functions.

Left unconstrained, quantitative repositories accumulate hand-written `FastAPI`/`Flask`/`Streamlit`/`Dash` servers under `src/` or `scripts/`, inline-Python `http.server` shims, unpinned frontend bundles, TradingView CDP automation, and commercial EULA grid tiers (`AG Grid Enterprise`). Alongside [ADR-0017](ADR-0017.md) (which supersedes the hosting/15-portal observability half), this ADR **supersedes [ADR-0011](ADR-0011.md) (Superseded)** as the authoritative architecture for `L10` institutional UI, declarative data contracts, plugin governance, and earned-trigger multimodal workbench evolution.

## Decision Drivers

- **Zero Hand-Written HTML/JS/TS or Web Servers in `src/` and `scripts/`:** Production Python writes data contracts (JSON, Markdown, watchlists, Parquet, `DuckDB`) and calls upstream report functions; the interfaces that show them are upstream ones. Under the dashboards rule (owner decision `2026-11-27`) it also composes no figure, page or table; two figure specifications predating the rule are still open (change note below).
- **Strict SPDX OSI License Firewall & Deployment Policy Separation:** Admit only verified OSI-approved licenses (`Apache-2.0`, `MIT`, `BSD-3-Clause`, `MPL-2.0`, `LGPL-3.0-only`). For **`grafana/grafana` (`13.3.2`, SPDX `AGPL-3.0-only`)**, separate its OSI SPDX license from the repository deployment policy: run strictly **unmodified, loopback-only (`127.0.0.1:3001`), never imported into `src/`, and never network-exposed** (especially material because local Grafana uses anonymous Admin). Explicitly exclude non-OSI licenses (`Arize-ai/phoenix` `ELv2`) and commercial EULAs (`AG Grid Enterprise`, `Dagster+`, `evidence` cloud) while admitting `MIT`-licensed `ag-grid-community`.
- **Loopback-Only, Fail-Closed Safety Invariants:** Bind every `L10` surface to `127.0.0.1` with zero live broker ports (`:4001`, `:7496`, `:8798`, `:8796`), staged tickets at `semi_auto_confirmed = False` / `qty = 1` until the operator confirms, read-only mounts, and immutable `src/tier0_sota/risk.py`; live operations follow the three tiers of [ADR-0029](ADR-0029.md) (`live_execution_enabled = False` means tier 3 is off).
- **Checksum-Pinned Plugin & CLI Governance:** Manage FINOS Workspace widget plugins exclusively via `scripts.plugin_check --digest`, `WIDGET_PLUGINS_PINS` (`WIDGET_PLUGINS_REQUIRE_PINS=true`), CSP/network overrides, RBAC grants, and stdin-only secrets via `python -m scripts.workspace_admin`.
- **Earned-Trigger Multimodal Workbench Evolution:** Track OSI `L10`/`L14` workbenches (`marimo`, `rerun`, `mosaic`, `FDC3`, `evidence`) behind quantified promotion triggers.

## Considered Options

1. **Custom `FastAPI`/`Streamlit`/`Dash` or Hand-Written React/HTML/JS Cockpit under `src/` and `scripts/`** — violates Zero Self-Invention (`no-custom-dashboard-server`, `no-handwritten-web-assets`) and creates unmaintained frontend security debt.
2. **Commercial Proprietary Terminal / `AG Grid Enterprise` or TradingView CDP Automation** — violates the SPDX OSI firewall or TradingView ToU ([ADR-0010](ADR-0010.md)).
3. **Declarative-Contract `L10` Institutional Stack (`FINOS Workspace` `:1420`/`:8000` + `OpenBB` `:6900` + `finos/perspective` + `lightweight-charts` v5 + `ag-grid-community` + `DuckDB SQL UI` `:4213` + `Caddy` Tearsheets `:8793` + Display-Only Pine v6 Cockpit) with Zero Self-Edit UI Mechanical Gates and Earned-Trigger `L10`/`L14` Workbench Watches (chosen)**.

## Decision Outcome

Adopt **Option 3** (superseding the `L10` UI half of [ADR-0011](ADR-0011.md) (Superseded)), reinforcing [ADR-0001](ADR-0001.md), [ADR-0009](ADR-0009.md), [ADR-0010](ADR-0010.md), [ADR-0017](ADR-0017.md), [ADR-0018](ADR-0018.md), and [ADR-0020](ADR-0020.md).

**Dashboards rule (owner decision `2026-11-27`, "Upstream UIs + config"):** the interfaces the upstream projects ship are used as they are; configuration written here for upstream platforms stays (Grafana dashboard JSON for the harness's own metrics, Prometheus rules and scrape targets, Alertmanager routes, the collector config, the Caddyfile); every figure, page or table renderer written here is replaced by the upstream's own function; the four Pine scripts and three TradingView documents are the TradingView lane's named exception; the end state is no HTML, CSS, JS, template or figure code written in this repository outside that exception. Report pages are interactive pages written by upstream report functions, one call per file with run data only (Form A below; [ADR-0016](ADR-0016.md)), and the `ast-grep` rule `no-handbuilt-plotly-chart` (severity `error`, `src/**/*.py` + `scripts/**/*.py`) makes hand-built figure code unmergeable: Plotly imports (incl. `plotly.graph_objects` / `plotly.express` / `plotly.subplots`) and `matplotlib.pyplot` imports, `go.Figure(...)`, `make_subplots(...)`, `combine_figures_to_html(...)`, `.add_trace(...)` and `.to_html(...)` on DataFrames or Stylers.

### 2. Real-Time 24/5 Trading Cockpit & Declarative Data Contracts

For the initial migration, stop `tier0-duckdb-ui`, run one successful `just paper-farm` observation, then run `bash scripts/configure_paper_farm_ui.sh` in Noesis-SOTA. The systemd drop-in binds the three view catalogs into the UI service's mount namespace and restarts the service. The writer continues to use `Z:\sota-data\manifests\paper_lane_{pa1,pa2,pa3}.duckdb`.

Production Python emits validated atomic data contracts. Two of them still carry figure specifications written here, which the dashboards rule retires (open, see the change note): the Plotly bar traces and layout in `finos_paper_farm_performance.json` (`src/tier0_sota/live/performance.py`) and in `finos_tv_cockpit.json` (`src/tier0_sota/tv/tickets.py`, which also writes a lightweight-charts marker and price-line spec):

- **Paper Farm Export (`src/tier0_sota/live/performance.py`):** `PaperPerformanceAggregator` snapshots per-lane `DuckDB` ledgers via read-only temp copies (`shutil.copy2`) and writes `paper_farm_live_performance_manifest.json` and `finos_paper_farm_performance.json` (`plugin: "@finos-workspace/plotly-charts@2.5.0"`, `openbb_rows`, `paper_only: true`, `live_execution_enabled: false`).
- **24/5 Half-Auto TradingView Cockpit (`src/tier0_sota/tv/{bridge,tickets}.py`, `pine/*.pine`, `scripts/tv_console.{ps1,sh}`, extended by [ADR-0027](ADR-0027.md)):** Enforces strict Pydantic v2 `TvAlertV1` (`extra="forbid"`, `Decimal` prices, `bar_confirmed=True`, `qty=1`, `semi_auto_confirmed=False`, `MAX_INPUT_AGE_MS = 900_000`, `XNYS` parity, Rule-612 `<= 2.00%`, ETB/inverse routing) and atomically emits `live_half_auto_tickets.json`, `LIVE_HALF_AUTO_ORDER_TICKETS.md`, `tv_order_presets.json`, `TV_ORDER_PRESET_CARDS.md`, exchange-qualified 6-section `tier0_sota_tv_watchlists_live.txt`, declarative `finos_tv_cockpit.json` (`lightweight-charts` v5 `UTCTimestamp`-seconds markers/rungs + `openbb_rows`), `tv_compounding_manifest.json`, and `tv_half_auto_audit.duckdb` + `tv_staged_presets.parquet` (`tradingview/charting_library` proprietary license and `louisnw01/lightweight-charts-python` desktop WebView overlap remain blocked).
- **Observability & Sim-Backtest Control Center (`L6` / `L10`):** `Grafana` (`grafana/grafana:13.3.2`, `:3001`, `AGPL-3.0-only`, Explore and Metrics Drilldown, 4 dashboard JSON files for the harness's own metrics including `docker/grafana/dashboards/tier0-sim-backtest-control-center.json` [`3` panels]), `Prometheus` (`prom/prometheus:v3.16.0`, `:9090`), `Alertmanager` (`prom/alertmanager:v0.28.1`, `:9093` profile-gated), `otel/opentelemetry-collector-contrib:0.166.0` (`:9464/metrics`, `:13133`), `caddy:2.11.9-alpine` (`:8793/tearsheets/` serving the engine's `create_tearsheet` pages and the upstream report files), and OpenBB `:6900` sim control-center widgets (`/tier0/sim-backtest-coverage`, `/tier0/upstream-control-center-status`, defined in the out-of-tree backend and not served by the process running on `2026-11-27`) under [ADR-0017](ADR-0017.md).

### 3. Plugin Governance, Sandboxing & Zero Self-Edit UI Enforcement

- **FINOS Plugin Lifecycle (`.claude/skills/finos-{develop-plugins,administer-via-cli}/SKILL.md`):** Plugins live exclusively in external host repos (`Z:\sota-data\hosted-research-frameworks\finos-workspace-plugins`, `:ro`), conform to `manifestVersion: 1`, verify SHA-256 via `scripts.plugin_check --digest`, pin via `WIDGET_PLUGINS_PINS`, and administer strictly via `python -m scripts.workspace_admin --json` with stdin-only secrets.

## Consequences

- **Positive:** Delivers an OSI-clean institutional UI (`FINOS Workspace`, `OpenBB`, `Perspective`, `Lightweight Charts v5`, `ag-grid-community`, `DuckDB SQL UI`, `Caddy`, plus static `Allure Report 3` at `:8793/test-reports/allure/`) fed by data contracts and upstream report functions, with zero custom HTML/JS in `src/` or `scripts/` (two figure specifications still open, see the change note).

Additionally, running `tearsheets` (`caddy:2.11.9-alpine`) with `network_mode: host` (so Caddy can reverse-proxy `:4213` -> host `127.0.0.1:4214` DuckDB UI) removes Docker bridge port-publish isolation: loopback exposure now relies directly on `docker/Caddyfile` `bind 127.0.0.1` + `admin off`, which is mechanically pinned by `tests/test_grand_reset_kit.py::test_caddyfile_loopback_binding_and_duckdb_csrf_posture`.

## Pros and Cons of the Options

### Option 1: Custom `FastAPI`/`Streamlit`/`Dash` or bespoke React cockpit

- Good, because one developer can hack a local page rapidly.
- Bad, because it violates `no-custom-dashboard-server` / `no-handwritten-web-assets` and creates long-term frontend maintenance and XSS/CSP debt.

### Option 2: Commercial terminal / `AG Grid Enterprise` or TradingView CDP automation

- Good, because proprietary grids bundle enterprise pivoting.
- Bad, because commercial EULAs violate the SPDX OSI firewall and CDP violates TradingView ToU.

### Option 3: Declarative-contract `L10` OSI stack + external checksum-pinned plugins

- Good, because `noesis` keeps to Python data contracts and upstream report calls (no web assets) while leveraging institutional upstream UI engines.
- Bad, because custom visualization extensions must follow the external FINOS plugin build & checksum-pin workflow.
