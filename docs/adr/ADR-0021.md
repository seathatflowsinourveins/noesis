# ADR-0021: Institutional Analytics UI, Real-Time 24/5 Trading Cockpit & Multimodal Quantitative Workbench (L10)

## Context and Problem Statement

Operating a 24/5 quantitative trading and research workstation across four compounding harness lanes (`sim-backtest`, `paper`, `half-auto-tv`, `live`) requires institutional-grade visual analytics: multi-lane paper equity and drawdown telemetry, real-time extreme-mover watchlists and staged order tickets, high-density streaming blotters, sub-second SQL inspection over `DuckDB` and pre-wall Parquet lakes, and unmodified backtest/SHAP tearsheets.

Left unconstrained, quantitative repositories accumulate hand-written `FastAPI`/`Flask`/`Streamlit`/`Dash` servers under `src/` or `scripts/`, inline-Python `http.server` shims, unpinned frontend bundles, TradingView CDP automation, and commercial EULA grid tiers (`AG Grid Enterprise`). Alongside [ADR-0017](ADR-0017.md) (which supersedes the hosting/15-portal observability half), this ADR **supersedes [ADR-0011](ADR-0011.md) (Superseded)** as the authoritative architecture for `L10` institutional UI, declarative data contracts, plugin governance, and earned-trigger multimodal workbench evolution.

## Decision Drivers

- **Zero Hand-Written HTML/JS/TS or Web Servers in `src/` and `scripts/`:** Production Python emits strictly declarative data contracts (JSON, Markdown, watchlists, Parquet, `DuckDB`, unmodified upstream tearsheets) consumed exclusively by official upstream `L10` and `L6` platforms.
- **Strict SPDX OSI License Firewall & Deployment Policy Separation:** Admit only verified OSI-approved licenses (`Apache-2.0`, `MIT`, `BSD-3-Clause`, `MPL-2.0`, `LGPL-3.0-only`). For **`grafana/grafana` (`13.3.1`, SPDX `AGPL-3.0-only`)**, separate its OSI SPDX license from the repository deployment policy: run strictly **unmodified, loopback-only (`127.0.0.1:3001`), never imported into `src/`, and never network-exposed** (especially material because local Grafana uses anonymous Admin). Explicitly exclude non-OSI licenses (`Arize-ai/phoenix` `ELv2`) and commercial EULAs (`AG Grid Enterprise`, `Dagster+`, `evidence` cloud) while admitting `MIT`-licensed `ag-grid-community`.
- **Loopback-Only, Fail-Closed Safety Invariants:** Bind every `L10` surface to `127.0.0.1` with zero live broker ports (`:4001`, `:7496`, `:8798`, `:8796`), `paper_only = True`, `live_execution_enabled = False`, `semi_auto_confirmed = False`, `qty = 1`, read-only mounts, and immutable `src/tier0_sota/risk.py`.
- **Checksum-Pinned Plugin & CLI Governance:** Manage FINOS Workspace widget plugins exclusively via `scripts.plugin_check --digest`, `WIDGET_PLUGINS_PINS` (`WIDGET_PLUGINS_REQUIRE_PINS=true`), CSP/network overrides, RBAC grants, and stdin-only secrets via `python -m scripts.workspace_admin`.
- **Earned-Trigger Multimodal Workbench Evolution:** Track OSI `L10`/`L14` workbenches (`marimo`, `rerun`, `mosaic`, `FDC3`, `evidence`) behind quantified promotion triggers.

## Considered Options

1. **Custom `FastAPI`/`Streamlit`/`Dash` or Hand-Written React/HTML/JS Cockpit under `src/` and `scripts/`** — violates Zero Self-Invention (`no-custom-dashboard-server`, `no-handwritten-web-assets`) and creates unmaintained frontend security debt.
2. **Commercial Proprietary Terminal / `AG Grid Enterprise` or TradingView CDP Automation** — violates the SPDX OSI firewall or TradingView ToU ([ADR-0010](ADR-0010.md)).
3. **Declarative-Contract `L10` Institutional Stack (`FINOS Workspace` `:1420`/`:8000` + `OpenBB` `:6900` + `finos/perspective` + `lightweight-charts` v5 + `ag-grid-community` + `DuckDB SQL UI` `:4213` + `Caddy` Tearsheets `:8793` + Display-Only Pine v6 Cockpit) with Zero Self-Edit UI Mechanical Gates and Earned-Trigger `L10`/`L14` Workbench Watches (chosen)**.

## Decision Outcome

Adopt **Option 3** (superseding the `L10` UI half of [ADR-0011](ADR-0011.md) (Superseded)), reinforcing [ADR-0001](ADR-0001.md), [ADR-0009](ADR-0009.md), [ADR-0010](ADR-0010.md), [ADR-0017](ADR-0017.md), [ADR-0018](ADR-0018.md), and [ADR-0020](ADR-0020.md).

### 2. Real-Time 24/5 Trading Cockpit & Declarative Data Contracts

For the initial migration, stop `tier0-duckdb-ui`, run one successful `just paper-farm` observation, then run `bash scripts/configure_paper_farm_ui.sh` in Noesis-SOTA. The systemd drop-in binds the three view catalogs into the UI service's mount namespace and restarts the service. The writer continues to use `Z:\sota-data\manifests\paper_lane_{pa1,pa2,pa3}.duckdb`.

Zero UI code lives in `src/tier0_sota/`. Production Python emits validated atomic declarative contracts:

## Consequences

- **Positive:** Delivers an OSI-clean institutional UI (`FINOS Workspace`, `OpenBB`, `Perspective`, `Lightweight Charts v5`, `ag-grid-community`, `DuckDB SQL UI`, `Caddy`, plus static `Allure Report 3` at `:8793/test-reports/allure/`) fed solely by declarative contracts with zero custom HTML/JS in `src/` or `scripts/`.
- **Negative & Security Boundary:** Prohibits quick custom web endpoints inside Python source trees, requiring new widgets to ship as checksum-pinned external FINOS/OpenBB plugins or declarative JSON/Parquet exports. Additionally, running `tearsheets` (`caddy:2.11.9-alpine`) with `network_mode: host` (so Caddy can reverse-proxy `:4213` -> host `127.0.0.1:4214` DuckDB UI) removes Docker bridge port-publish isolation: loopback exposure now relies directly on `docker/Caddyfile` `bind 127.0.0.1` + `admin off`, which is mechanically pinned by `tests/test_grand_reset_kit.py::test_caddyfile_loopback_binding_and_duckdb_csrf_posture`.

## Pros and Cons of the Options

### Option 1: Custom `FastAPI`/`Streamlit`/`Dash` or bespoke React cockpit

- Good, because one developer can hack a local page rapidly.
- Bad, because it violates `no-custom-dashboard-server` / `no-handwritten-web-assets` and creates long-term frontend maintenance and XSS/CSP debt.

### Option 2: Commercial terminal / `AG Grid Enterprise` or TradingView CDP automation

- Good, because proprietary grids bundle enterprise pivoting.
- Bad, because commercial EULAs violate the SPDX OSI firewall and CDP violates TradingView ToU.

### Option 3: Declarative-contract `L10` OSI stack + external checksum-pinned plugins

- Good, because `noesis` stays 100% clean Python/data contracts while leveraging institutional upstream UI engines.
- Bad, because custom visualization extensions must follow the external FINOS plugin build & checksum-pin workflow.
