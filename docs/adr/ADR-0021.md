# ADR-0021: Institutional Analytics UI, Real-Time 24/5 Trading Cockpit & Multimodal Quantitative Workbench (L10)

## Context and Problem Statement

Operating a 24/5 quantitative trading and research workstation across four compounding harness lanes (`sim-backtest`, `paper`, `half-auto-tv`, `live`) requires institutional-grade visual analytics: multi-lane paper equity and drawdown telemetry, real-time extreme-mover watchlists and staged order tickets, high-density streaming blotters, sub-second SQL inspection over `DuckDB` and pre-wall Parquet lakes, and backtest/attribution reports drawn by the upstream libraries' own report and plot functions.

Left unconstrained, quantitative repositories accumulate hand-written `FastAPI`/`Flask`/`Streamlit`/`Dash` servers under `src/` or `scripts/`, inline-Python `http.server` shims, unpinned frontend bundles, TradingView CDP automation, and commercial EULA grid tiers (`AG Grid Enterprise`). Alongside [ADR-0017](ADR-0017.md) (which supersedes the hosting/15-portal observability half), this ADR **supersedes [ADR-0011](ADR-0011.md) (Superseded)** as the authoritative architecture for `L10` institutional UI, declarative data contracts, plugin governance, and earned-trigger multimodal workbench evolution.

## Decision Drivers

- **Zero Hand-Written HTML/JS/TS or Web Servers in `src/` and `scripts/`:** Production Python writes data contracts (JSON, Markdown, watchlists, Parquet, `DuckDB`) and calls upstream report functions; the interfaces that show them are upstream ones. Under the dashboards rule (owner decision `2026-11-27`) it also composes no figure, page or table; two figure specifications predating the rule are still open (change note below).
- **Strict SPDX OSI License Firewall & Deployment Policy Separation:** Admit only verified OSI-approved licenses (`Apache-2.0`, `MIT`, `BSD-2-Clause`, `BSD-3-Clause`, `MPL-2.0`, `LGPL-3.0-only`, and `AGPL-3.0-only` for unmodified deployment-only services). Until a license allow-list check over the locked packages lands: 'no check holds `uv.lock` to this list: `spdx_license_firewall` in `upstream-map.toml` names `7` excluded projects, and `just license-audit` runs Trivy with `--severity HIGH,CRITICAL` over the repository and over the installed wheels (the wheel scan ignores `LGPL-3.0-only`); locked packages also declare `ISC`, `NCSA`, `PSF-2.0`, `MIT-0`, `MIT-CMU`, `CNRI-Python`, `Apache-2.0 WITH LLVM-exception` and `CC-BY-4.0` (`colorcet` `3.2.1`) in their metadata (read at `6349e94`, `2026-11-28`)'. For **`grafana/grafana` (`13.3.2`, SPDX `AGPL-3.0-only`)**, separate its OSI SPDX license from the repository deployment policy: run strictly **unmodified, loopback-only (`127.0.0.1:3001`), never imported into `src/`, and never network-exposed** (especially material because local Grafana uses anonymous Admin). Explicitly exclude non-OSI licenses (`Arize-ai/phoenix` `ELv2`) and commercial EULAs (`AG Grid Enterprise`, `Dagster+`, `evidence` cloud) while admitting `MIT`-licensed `ag-grid-community`.
- **Loopback-Only, Fail-Closed Safety Invariants:** Bind every `L10` surface to `127.0.0.1` with zero live broker ports (`:4001`, `:7496`, `:8798`, `:8796`), `paper_only = True`, `live_execution_enabled = False`, `semi_auto_confirmed = False`, `qty = 1`, read-only mounts, and immutable `src/tier0_sota/risk.py`.
- **Checksum-Pinned Plugin & CLI Governance:** Manage FINOS Workspace widget plugins exclusively via `scripts.plugin_check --digest`, `WIDGET_PLUGINS_PINS` (`WIDGET_PLUGINS_REQUIRE_PINS=true`), CSP/network overrides, RBAC grants, and stdin-only secrets via `python -m scripts.workspace_admin`.
- **Earned-Trigger Multimodal Workbench Evolution:** Track OSI `L10`/`L14` workbenches (`marimo`, `rerun`, `mosaic`, `FDC3`, `evidence`) behind quantified promotion triggers.

## Considered Options

1. **Custom `FastAPI`/`Streamlit`/`Dash` or Hand-Written React/HTML/JS Cockpit under `src/` and `scripts/`** — violates Zero Self-Invention (`no-custom-dashboard-server`, `no-handwritten-web-assets`) and creates unmaintained frontend security debt.
2. **Commercial Proprietary Terminal / `AG Grid Enterprise` or TradingView CDP Automation** — violates the SPDX OSI firewall or TradingView ToU ([ADR-0010](ADR-0010.md)).
3. **Declarative-Contract `L10` Institutional Stack (`FINOS Workspace` `:1420`/`:8000` + `OpenBB` `:6900` + `finos/perspective` + `lightweight-charts` v5 + `ag-grid-community` + `DuckDB SQL UI` `:4213` + `Caddy` Tearsheets `:8793` + Display-Only Pine v6 Cockpit) with Zero Self-Edit UI Mechanical Gates and Earned-Trigger `L10`/`L14` Workbench Watches (chosen)**.

## Decision Outcome

Adopt **Option 3** (superseding the `L10` UI half of [ADR-0011](ADR-0011.md) (Superseded)), reinforcing [ADR-0001](ADR-0001.md), [ADR-0009](ADR-0009.md), [ADR-0010](ADR-0010.md), [ADR-0017](ADR-0017.md), [ADR-0018](ADR-0018.md), and [ADR-0020](ADR-0020.md).

**Dashboards rule (owner decision `2026-11-27`, "Upstream UIs + config"):** the interfaces the upstream projects ship are used as they are; configuration written here for upstream platforms stays (Grafana dashboard JSON for the harness's own metrics, Prometheus rules and scrape targets, Alertmanager routes, the collector config, the Caddyfile); every figure, page or table renderer written here is replaced by the upstream's own function; the four Pine scripts and three TradingView documents are the TradingView lane's named exception; the end state is no HTML, CSS, JS, template or figure code written in this repository outside that exception. Report pages are interactive pages written by upstream report functions, one call per file with run data only (Form A below; [ADR-0016](ADR-0016.md)), and the `ast-grep` rule `no-handbuilt-plotly-chart` (severity `error`, `src/**/*.py` + `scripts/**/*.py`) makes hand-built figure code unmergeable: Plotly imports (incl. `plotly.graph_objects` / `plotly.express` / `plotly.subplots`) and `matplotlib.pyplot` imports, `go.Figure(...)`, `make_subplots(...)`, `combine_figures_to_html(...)`, `.add_trace(...)` and `.to_html(...)` on DataFrames or Stylers.

### 2. Real-Time 24/5 Trading Cockpit & Declarative Data Contracts

For the initial migration, stop `tier0-duckdb-ui`, run one successful `just paper-farm` observation, then run `bash scripts/configure_paper_farm_ui.sh` in Noesis-SOTA. The systemd drop-in binds the three view catalogs into the UI service's mount namespace and restarts the service. The writer continues to use `Z:\sota-data\manifests\paper_lane_{pa1,pa2,pa3}.duckdb`.

Production Python emits validated atomic data contracts. Two of them still carry figure specifications written here, which the dashboards rule retires (open, see the change note): the Plotly bar traces and layout in `finos_paper_farm_performance.json` (`src/tier0_sota/live/performance.py`) and in `finos_tv_cockpit.json` (`src/tier0_sota/tv/tickets.py`, which also writes a lightweight-charts marker and price-line spec):

### 6. Why Open-Source Trading Engines Omit Bundled Web Dashboards & Native Upstream Dashboard Audit (`2026-11-28`)

Primary-source inspection of both top-tier US Equities & US Options `Sim == Paper == Live` engines (persisted in `/mnt/z/sota-data/manifests/us_equities_options_sota_convergence_manifest.json`) proves that omitting a bundled interactive web dashboard from open-source trading kernels is **intentional architecture, not a missing feature**:

- **Empirical OSS vs Commercial UI Reality:**
  - **`NautilusTrader OSS` (`2.0.0rc9`, `LGPL-3.0-only`):** Ships zero live web dashboard by design. Official OSS outputs are local Plotly HTML tearsheets (`nautilus_trader.analysis.tearsheet`: `create_tearsheet`, `create_bars_with_fills`) plus open egress via `ParquetDataCatalog`, `RedisMessageBusConfig`, and `PostgresCacheConfig`. Centralized web Dashboard UIs, Control Plane APIs, and codebase MCP are explicitly separated into commercial **`NautilusTrader Pro`** and **`Nautilus Cloud`**.
  - **`QuantConnect / LEAN OSS` (`Apache-2.0`, `lean-cli` `336★`):** Also ships **NO local live web dashboard** — QuantConnect explicitly deprecated its local GUI web server. Local OSS ships only static **`QuantConnect.Report`** (`lean report` -> `report.html`). Interactive web IDE, equity/drawdown/capacity/options-Greeks charts, optimization heatmaps, Mia AI, and closed Remote MCP (`https://www.quantconnect.com/api/v2/mcp`) are exclusive to **Paid QuantConnect Cloud**.
- **Three Structural Causes:**
  1. **Hot-Path Determinism, Latency & Blast-Radius Isolation:** Embedding HTTP/WebSocket servers, JS bundlers, OAuth/RBAC, and SQL migrations inside a Rust/C# execution/risk OMS introduces GC/memory jitter, CVE exposure, and crash blast radius that can drop protective stops or risk latches.
  2. **Open-Core Commercial Monetization Boundary:** Vendors keep the headless `L3` engine open-source for ecosystem adoption while monetizing hosted multi-node UIs, control planes, and bundled OPRA data (`Nautilus OSS` vs `Pro/Cloud`; `LEAN OSS` vs `QC Cloud`).
  3. **Institutional Separation of Concerns (`L3` Headless OMS -> `L6`/`L10` Specialized Read-Only UIs):** No trading-engine team can out-build five distinct upstream UI disciplines simultaneously — (a) time-series telemetry & alerting (`Prometheus`/`Alertmanager`/`Grafana`), (b) experiment/HPO/eval ledgers (`MLflow 3`/`Optuna Dashboard`/`Dagster`/`Inspect`/`Zensical`), (c) institutional multi-widget terminals & US options chain widgets (`OpenBB v5` `75,807★` `Apache-2.0` + `FINOS Workspace` + `Perspective` + `Lightweight Charts v5` + `AG Grid Community`), (d) reactive Python/SQL workbenches (`marimo 0.26.0` `23,778★` `Apache-2.0` live **7-tab** workbench on `:2718` covering DuckDB SQL, Optuna RDB, MLflow 3, Strategy E2E, and landscape evidence), and (e) native upstream report pages (`Nautilus` `create_tearsheet`/`create_bars_with_fills`, `ml4t-diagnostic` 5-tab backtest + 4-tab feature importance, `skfolio` `plot_train_test_folds`/`Population.plot_distribution`, `Allure 3.33.0`).
- **Companion Broker & 4-Tier Paid/SaaS LLM-Native UI Audit (`2026-11-28`):**
  - *Tier-1 Code-First Cloud UIs:* **`QuantConnect Cloud`** is the sole GA Tier-1 cloud SaaS bundling interactive 2D/3D optimization heatmaps, PSR/OPRA Greeks charts, live monitor, and 60+ executable Remote MCP tools (`~$34/mo` min; optional off-repo US Options research lab only); **`NautilusTrader Pro`** provides a `1`-node Free / multi-node Paid Dashboard + hosted docs MCP (`2–5` tools / `10–200 req/day`), with `Nautilus Cloud` rolling out; **`TradingView`** Supercharts + OAuth 2.1 MCP (`38` tools) remains our active half-auto visual companion.
  - *Tier-2 Retail/Prosumer & Defunct SaaS:* **`Option Omega`** (`https://mcp.optionomega.com/mcp`, backtest-only MCP + 1m/1s-IMSL SPX/SPY 0DTE web UI), **`NexusTrade`** (OAuth MCP `100+` tools retail UI), **`Composer`** (REST-only daily Symphony UI), **`ORATS`** (web IV-surface UI + optional paid REST data feed), `Option Alpha`/`OptionStrat`/`OptionNet Explorer`/`Wealth-Lab`/`RealTest`/`Portfolio123`/`QuantRocket` are never imported into `noesis`; **`SigTech`** is permanently defunct and **`Capitalise.ai`** was acquired by Kraken.
  - *Tier-3 Broker Reconciliation & Data MCPs:* Broker-native portals (`IBKR PortfolioAnalyst` / `TWS Risk Navigator` + **`IBKR` Official Public MCP** `https://api.ibkr.com/v1/api/mcp-public`, and `Alpaca Web Dashboard` + off-repo paper-only `alpaca-sota-mcp`) serve as authoritative broker-of-record companions, alongside data-only MCPs (`massive-com/mcp_massive` `404★`, `openbb-mcp-server` `v2.0.1`).

## Consequences

- **Positive:** Delivers an OSI-clean institutional UI (`FINOS Workspace`, `OpenBB`, `Perspective`, `Lightweight Charts v5`, `ag-grid-community`, `DuckDB SQL UI`, `Caddy`, plus static `Allure Report 3` at `:8793/test-reports/allure/`) fed by data contracts and upstream report functions, with zero custom HTML/JS in `src/` or `scripts/` (two figure specifications still open, see the change note).
- **Negative & Security Boundary:** Prohibits quick custom web endpoints inside Python source trees, requiring new widgets to ship as checksum-pinned external FINOS/OpenBB plugins or declarative JSON/Parquet exports. Additionally, running `tearsheets` (`caddy:2.11.9-alpine`) with `network_mode: host` (so Caddy can reverse-proxy `:4213` -> host `127.0.0.1:4214` DuckDB UI) removes Docker bridge port-publish isolation: loopback exposure now relies directly on `docker/Caddyfile` `bind 127.0.0.1` + `admin off`, which is mechanically pinned by `tests/test_grand_reset_kit.py::test_caddyfile_loopback_binding_and_duckdb_csrf_posture`.

## Pros and Cons of the Options

### Option 1: Custom `FastAPI`/`Streamlit`/`Dash` or bespoke React cockpit

- Good, because one developer can hack a local page rapidly.
- Bad, because it violates `no-custom-dashboard-server` / `no-handwritten-web-assets` and creates long-term frontend maintenance and XSS/CSP debt.

### Option 2: Commercial terminal / `AG Grid Enterprise` or TradingView CDP automation

- Good, because proprietary grids bundle enterprise pivoting.
- Bad, because commercial EULAs violate the SPDX OSI firewall and CDP violates TradingView ToU.

### Option 3: Declarative-contract `L10` OSI stack + external checksum-pinned plugins

- Good, because `noesis` keeps to Python data contracts and upstream report calls (no web assets) while leveraging institutional upstream UI engines.
- Bad, because custom visualization extensions must follow the external FINOS plugin build & checksum-pin workflow.
