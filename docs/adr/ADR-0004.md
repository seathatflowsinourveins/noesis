# ADR-0004: Single-Engine Trading Parity (`NautilusTrader v2` + Rust `hftbacktest`)

- **Status:** Accepted
- **Date:** 2026-11-25
- **Evidence Grade:** E4

## Context and Problem Statement

Maintaining separate simulation and live/paper strategy codebases produces divergence in fill timing, stop triggers, order throttling, and position state transitions.

## Decision Drivers

- Identical strategy logic across `BacktestEngine`, `Environment.SANDBOX`, and `LiveNode`.
- Realistic L2/queue-position slippage and markout simulation via Rust `hftbacktest`.
- Native `RiskEngineConfig` / `LiveRiskEngineConfig` rate pacing without custom shadow order managers.

## Considered Options

1. **Custom Python backtest loop alongside separate live broker scripts** — violates `Sim == Paper == Live` parity.
2. **Unified `NautilusTrader v2` (`SignalExecutionStrategy`) + Rust `hftbacktest` queue simulation**.

## Decision Outcome

Adopt Option 2. `src/tier0_sota/engine.py` lives directly inside `NautilusTrader v2` (`BacktestEngine`, `LiveNode`, `RiskEngineConfig`, `OrderEmulator`, `SignalExecutionStrategy`) with `bypass=False` rate pacing and Rust `hftbacktest` queue-depth/markout evaluation. Custom shadow engine/pacer classes are prohibited by `ast-grep`.

### Consequences

- **Positive:** Zero behavioral drift between pre-wall simulation, 24/7 sandbox replay, and paper farm execution.
- **Negative:** All execution extensions must conform to `NautilusTrader v2` actor/strategy contracts.
