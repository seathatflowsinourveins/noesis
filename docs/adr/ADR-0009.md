# ADR-0009: Stationary 4-Account Paper Farm Compounding Lane (ALPACA_PA1..PA3 + IBKR_DU_4002)

## Context and Problem Statement

Validating multiple intraday archetypes (`ORB Burst`, `Structural Trend`, `AVWAP Tight Lock`) in live markets requires non-overlapping symbol ownership, isolated per-account fill/markout ledgers, continuous compounding manifests, and mechanical isolation from live real-capital broker endpoints.

## Decision Drivers

- Collect continuous ungated live-market merit evidence in the `paper` compounding lane on the stationary Noesis host (`MAC_BROKER_PORTS = 0`) as Stage-2 evidence under [ADR-0020](ADR-0020.md).
- Prevent symbol collisions across `ALPACA_PA1` (`L1_ORB_BURST`), `ALPACA_PA2` (`L2_STRUCTURAL_TREND`), and `ALPACA_PA3` (`L3_AVWAP_TIGHT_LOCK`), alongside `IBKR_DU_4002` (profile target `3,000 rpm`, 24/5 overnight; tracked remediation of `paper_farm.py` `rate_budget_max_rpm=1000` and off-hours exit parity in [ADR-0019](ADR-0019.md)).
- Aggregate performance into declarative JSON manifests for `FINOS`, `OpenBB`, `Grafana`, and `OTel` without custom web servers ([ADR-0021](ADR-0021.md)).
- Inject paper credentials seamlessly across Windows and WSL2 via encrypted `fnox --profile paper` ([ADR-0023](ADR-0023.md)).

## Considered Options

1. **Single shared paper account with mixed strategies** — corrupts per-archetype attribution and creates cross-strategy order races.
2. **Isolated 4-account Paper Farm (`paper_only=True`, `live_execution_enabled=False`) with `CrossLaneSymbolLock`, isolated `DuckDB` ledgers, and declarative `FINOS`/`OpenBB` manifests**.

## Decision Outcome

Adopt Option 2 in `src/tier0_sota/live/paper_farm.py` and `src/tier0_sota/live/performance.py`. Each lane tracks independent status JSON and `DuckDB` telemetry (`paper_lane_{pa1,pa2,pa3}.duckdb`), acquires symbols exclusively via `CrossLaneSymbolLock`, enforces `ProtectiveExitRateBudget` (`200 rpm` Alpaca / `IBKR_PAPER_4002` paper profile, with tracked `IbkrPaperAdapter` `1000` -> `3000` rpm and confirmed-fill TCA schema remediation in [ADR-0019](ADR-0019.md)), and aggregates equity, drawdown, fills, auto-shorts, reverses, re-entries, and fast-sells into `Z:\sota-data\manifests\paper_farm_live_performance_manifest.json` and `finos_paper_farm_performance.json`.

## Consequences

- **Positive:** Isolates per-archetype fills, `DuckDB` ledgers, and `CrossLaneSymbolLock` ownership across `ALPACA_PA1..PA3` + `IBKR_DU_4002` with zero cross-lane symbol collisions or live port exposure.
- **Negative:** Requires reconciling 4 separate paper account ledgers, enforcing `CrossLaneSymbolLock` exclusivity, and completing [ADR-0019](ADR-0019.md) broker-fill TCA and `IbkrPaperAdapter` RPM alignment before Stage-4/5 promotion.

## Pros and Cons of the Options

### Option 1: Single shared paper account with mixed strategies

- Good, because only one API key and one ledger exist.
- Bad, because strategies race over identical symbols, corrupt per-archetype PnL attribution, and starve a single `200 rpm` rate bucket.

### Option 2: Isolated 4-account Paper Farm + `CrossLaneSymbolLock` + isolated `DuckDB` ledgers

- Good, because each archetype owns its own rate budget, ledger, and attribution while declarative JSON manifests feed `FINOS`/`OpenBB`/`Grafana` with zero custom web servers.
- Bad, because four ledgers require unified aggregation (`PaperPerformanceAggregator`) and cross-lane locking.
