# ADR-0009: Stationary 4-Account Paper Farm Compounding Lane (ALPACA_PA1..PA3 + IBKR_DU_4002)

## Context and Problem Statement

Validating multiple intraday archetypes (`ORB Burst`, `Structural Trend`, `AVWAP Tight Lock`) in live markets requires non-overlapping symbol ownership, isolated per-account fill/TCA ledgers, extended-hours stop supervision, continuous compounding manifests, live OTel/Prometheus instrumentation, and mechanical isolation from live real-capital broker endpoints.

## Decision Drivers

- Collect continuous ungated live-market merit and realized TCA evidence in the `paper` compounding lane on the stationary Noesis host (`MAC_BROKER_PORTS = 0`) as Stage-2 evidence under [ADR-0020](ADR-0020.md).
- Prevent symbol collisions across `ALPACA_PA1` (`L1_ORB_BURST`), `ALPACA_PA2` (`L2_STRUCTURAL_TREND`), and `ALPACA_PA3` (`L3_AVWAP_TIGHT_LOCK`, `200 rpm` code default / **`1,000 rpm` live `ALPACA_PAPER_1000`** per lane via `TIER0_ALPACA_RPM=1000`), alongside `IBKR_DU_4002` (`3,000 rpm`, `300 rpm` protective exit reserve, 24/5 overnight -> **`6,000 rpm` configured combined / `600 rpm` `10%` exit reserve** once IBKR DU handshake is verified).
- Separate `orders_submitted` from confirmed `fills`, attach fail-closed extended-hours collared `STOP_LIMIT` protective supervision (`COLLARED_STOP_LIMIT_SUPERVISED`), persist exact-`Decimal` `paper_tca_fills` in isolated `DuckDB` ledgers, and export metrics via official `prometheus_client` + `opentelemetry` ([ADR-0019](ADR-0019.md)) plus declarative JSON manifests for `FINOS` and `OpenBB` ([ADR-0021](ADR-0021.md)).
- Inject paper credentials seamlessly across Windows and WSL2 via encrypted `fnox --profile paper` ([ADR-0023](ADR-0023.md)).

## Considered Options

1. **Single shared paper account with mixed strategies** — corrupts per-archetype attribution and creates cross-strategy order races.
2. **Isolated 4-account Paper Farm (`paper_only=True`, `live_execution_enabled=False`) with `CrossLaneSymbolLock`, extended-hours collared stop supervision, isolated `DuckDB` + `paper_tca_fills` ledgers, live OTel/Prometheus export, and declarative `FINOS`/`OpenBB` manifests (chosen)**.

## Decision Outcome

Adopt Option 2 in `src/tier0_sota/live/paper_farm.py` and `src/tier0_sota/live/performance.py`. Each lane tracks independent status JSON and `DuckDB` telemetry (`paper_lane_{pa1,pa2,pa3}.duckdb` including `paper_tca_fills`), acquires symbols exclusively via `CrossLaneSymbolLock`, enforces `ProtectiveExitRateBudget` (`200 rpm` Alpaca / `3,000 rpm` `IBKR_DU_4002`, `>= 10%` exit reserve), separates `orders_submitted` from confirmed `fills`, enforces `COLLARED_STOP_LIMIT_SUPERVISED` on extended-hours orders ([ADR-0019](ADR-0019.md)), exports live `prometheus_client` + `opentelemetry.metrics` telemetry with zero custom HTTP servers, and aggregates equity, drawdown, TCA (`mean_is_bps`, `p95_is_bps`, `total_borrow_fee_usd`, `extended_hours_protected_ratio`, `submitted_vs_filled_ratio`), fills, auto-shorts, reverses, re-entries, and fast-sells into `Z:\sota-data\manifests\paper_farm_live_performance_manifest.json` and `finos_paper_farm_performance.json`.

## Consequences

- **Positive:** Isolates per-archetype fills, exact-`Decimal` TCA ledgers (`paper_tca_fills`), `CrossLaneSymbolLock` ownership, extended-hours stop supervision, `3,000 rpm` IBKR rate parity, and live OTel/Prometheus telemetry across `ALPACA_PA1..PA3` + `IBKR_DU_4002` with zero live port exposure.
- **Negative:** Requires reconciling 4 separate paper account ledgers and enforcing `CrossLaneSymbolLock` exclusivity when multiple strategies signal the same extreme mover.

## Pros and Cons of the Options

### Option 1: Single shared paper account with mixed strategies

- Good, because only one API key and one ledger exist.
- Bad, because strategies race over identical symbols, corrupt per-archetype PnL/TCA attribution, and starve a single `200 rpm` rate bucket.

### Option 2: Isolated 4-account Paper Farm + `CrossLaneSymbolLock` + `paper_tca_fills` + OTel/Prometheus export

- Good, because each archetype owns its rate budget, extended-hours protection, and DuckDB TCA ledger while feeding `FINOS`/`OpenBB`/`Grafana`/`OTel` with zero custom web servers.
- Bad, because four ledgers require unified aggregation (`PaperPerformanceAggregator`) and cross-lane locking.

### Self-Invention Lesson Learned & Mechanical Upstream Gate

- **Lesson Learned:** Earlier LOC-golfing edits compressed `paper_farm.py` into dense blocks, left `IbkrPaperAdapter` at `1,000 rpm`, skipped extended-hours stop supervision, and counted submissions as fills. Clean upstream integration resolved every defect under [ADR-0019](ADR-0019.md) with zero custom HTTP servers.
- **Mechanical Upstream Gates:** `rules/zero_self_invention.yml`, `tests/test_live_automation.py`, `evals/tier0_inspect_eval.py`, and `scripts/grand_reset/verify_grand_reset.ps1` (`paper_farm_readiness`, `live_broker_ports_zero`).
