# ADR-0019: Execution Quality, Transaction Cost Analysis (TCA), Implementation Shortfall, Borrow-Fee Accounting & 24/5 Smart Order Routing (SOR)

## Context and Problem Statement

The Core Trading Philosophy only compounds if the cost assumptions inside the 6-gate falsification suite ([ADR-0016](ADR-0016.md)) hold on realized fills. Earlier iterations of the repository predicted costs (`MakerTakerFeeModel(0.0004, 0.0004)`, `1x`/`2x` gate costs, `hftbacktest` L1 markout) without measuring realized broker execution quality, left `orders_submitted` conflated with `fills`, omitted short-borrow accrual, submitted `order_factory.market(...)` outside `RTH`, lacked extended-hours collared stop supervision on Alpaca, and ran `IbkrPaperAdapter` at `1,000 rpm` instead of the `3,000 rpm` `IBKR_PAPER_4002` profile.

This ADR establishes and verifies the upstream-native exact-`Decimal` TCA pipeline, Perold implementation-shortfall decomposition, short-borrow fee accounting, 24/5 broker-native route-selection policy, extended-hours stop supervision, `IBKR_DU_4002` `3,000 rpm` parity, and official `prometheus_client` + `opentelemetry.metrics` telemetry instrumentation — without inventing a TCA framework, without adding custom HTTP servers, without modifying immutable `src/tier0_sota/risk.py`, and keeping `live_execution_enabled = False` and `paper_only = True`.

## Decision Drivers

- **Close the predicted-vs-realized loop:** Reconcile every paper fill against assumed backtest costs (`MakerTakerFeeModel`, `1x`/`2x` gate costs, `hftbacktest` markout) via `Dagster` asset `sim_vs_paper_parity_reconciliation` so realized slippage can falsify a promoted strategy prior to Stage-4/5 ([ADR-0020](ADR-0020.md)).
- **Standard decomposition, not invented metrics:** Implement Perold (1988) implementation shortfall (delay, execution/impact, explicit fees, borrow, opportunity cost) in exact `Decimal`, aligned with amended SEC Rule 605 (`2026-08-01`) benchmarks.
- **Broker-compliant 24/5 routing & extended-hours protection:** Route collared `LIMIT` entries outside `RTH` (`35 bps` Pre/After, `50 bps` Overnight) reserving `MARKET` strictly for `RTH`; attach deterministic collared `STOP_LIMIT` protective supervision (`COLLARED_STOP_LIMIT_SUPERVISED`) on Alpaca extended-hours orders; align `IBKR_DU_4002` `ProtectiveExitRateBudget` to `3,000 rpm` (`300 rpm` exit reserve).
- **Official OTel/Prometheus telemetry with zero custom HTTP servers:** Instrument TCA and Paper Farm metrics via `prometheus_client` (`CollectorRegistry`) and `opentelemetry.metrics` (`opentelemetry-exporter-otlp`), strictly obeying `no-custom-dashboard-server`.
- **OSI-only licensing:** Zero commercial TCA suites; 100% OSI pinned `uv.lock` stack.

## Considered Options

1. **Keep static cost assumptions (`4.0`/`8.0 bps`) and conflated submission/fill counters** — conceals slippage, adverse selection, borrow drag, and off-hours reject risk.
2. **Adopt a commercial TCA suite or external R/Zipline slippage framework** — fails the SPDX OSI firewall or breaks `Sim == Paper == Live` parity with NautilusTrader.
3. **Build a custom smart order router / venue sweeper** — violates Zero Self-Invention and duplicates regulated broker routers (`IBKR SMART`, Alpaca/BOATS).
4. **Upstream-native exact-`Decimal` TCA + DuckDB `paper_tca_fills` persistence + broker-native 24/5 collared `LIMIT` routing + extended-hours stop supervision + official OTel/Prometheus instrumentation (chosen)**.

## Decision Outcome

Adopt **Option 4** across `src/tier0_sota/engine.py`, `src/tier0_sota/research.py`, `src/tier0_sota/live/paper_farm.py`, and `src/tier0_sota/live/performance.py`:

1. **Broker-Compliant 24/5 Entry & Protective Routing (`src/tier0_sota/engine.py` & `live/paper_farm.py`):**
   - `SignalExecutionStrategy` submits collared `LIMIT` orders (`self.order_factory.limit(...)` using the session's `limit_collar_bps` — `35 bps` in `PRE_MARKET`/`AFTER_HOURS`, `50 bps` in `OVERNIGHT` — rounded via exact `Decimal`/Rule-612 helpers) for all `outside_rth=True` sessions, reserving `self.order_factory.market(...)` strictly for `RTH`.
   - `AlpacaPaperLane.submit_guarded_entry` strictly separates `orders_submitted` from confirmed `fills` and attaches a deterministic fail-closed collared `STOP_LIMIT` protective supervision record (`protective_stop_mode="COLLARED_STOP_LIMIT_SUPERVISED"`, exact `Decimal` stop & collar limit clamped `<= 2.00%` via `risk.py`) whenever an order is routed in `PRE_MARKET`/`AFTER_HOURS`. Opening shorts in `OVERNIGHT` remain refused on Alpaca.
   - `IbkrPaperAdapter` (`IBKR_DU_4002`) aligns `rate_budget_max_rpm = 3000` (`>= 10%` protective exit reserve = `300 rpm`, `2,700` active entry rpm), matching `EXECUTION_VENUE_PROFILES["IBKR_PAPER_4002"]` and [ADR-0009](ADR-0009.md). Live profiles and live ports `4001/7496/8798/8796` remain hard-refused.
2. **Exact-`Decimal` Perold Implementation Shortfall & Borrow-Fee Accounting (`src/tier0_sota/live/paper_farm.py`):**
   - `compute_tca_record(...)` calculates signed Perold implementation shortfall (`s = +1` buy / `-1` sell) strictly in exact `Decimal`: arrival mid/px, execution fill px, signed `implementation_shortfall_bps`, `commission_fee_bps`, short ETB/HTB borrow accrual (`round_lot_up(qty) * prior_close * annual_rate / 360`, Friday = 3 calendar days, inverse-ETF drag equivalent for fail-closed `SOXS`/`SQQQ`), and `total_net_cost_bps`.
   - Persists validated Pydantic v2 TCA records into each lane's isolated DuckDB table (`paper_tca_fills`, `DECIMAL` money columns) alongside causal `DuckDB` `ASOF JOIN` / `Polars` `join_asof` markout windows (`1 s`, `5 s`, `60 s`, `300 s`).
3. **Predicted-vs-Realized Reconciliation (`n >= 16` realized fills & `skfolio` `8/3` CPCV `21` OOS paths `>= 16` / `cpcv_min_samples = 48` per independent `LONG`/`SHORT` leg):**
   - Realized per-side cost `<= 4.0 bps` (`1x`) keeps the backtest valid; `(4.0, 8.0]` bps makes `2x` binding; `> 8.0 bps` or realized 60 s markout `< -20.0 bps` falsifies the cost assumption and demotes the lane to `sim-backtest` for re-falsification at measured cost. Reconciled daily by `Dagster` asset `sim_vs_paper_parity_reconciliation`.
4. **Live TCA Aggregation & Official OTel/Prometheus Export (`src/tier0_sota/live/performance.py`):**
   - `PaperPerformanceAggregator` aggregates realized TCA metrics (`mean_is_bps`, `p95_is_bps`, `total_borrow_fee_usd`, `extended_hours_protected_ratio`, `submitted_vs_filled_ratio`) into `paper_farm_live_performance_manifest.json` and `finos_paper_farm_performance.json`.
   - Emits metrics through official `prometheus_client` (`CollectorRegistry`, `Gauge`, `Counter`) and `opentelemetry.metrics` (`opentelemetry-api`/`sdk`/`exporter-otlp`) routed to `otel-collector-contrib` (`:4317`/`:4318` -> `:9464/metrics`) with zero custom HTTP servers (`no-custom-dashboard-server`), remaining 100% offline-deterministic in tests.

   | Session (ET) | `IBKR_DU_4002` (`3,000 rpm`, DU handshake pending) | `ALPACA_PA1..PA3` (`1,000 rpm` live `ALPACA_PAPER_1000` / `200 rpm` default) | Entry order | Protective exit | Opening shorts |
   |---|---|---|---|---|---|
   | `RTH` 09:30–16:00 | `SMART` | Alpaca default | Market / collared `LIMIT` | Native `STOP_MARKET` (`OTO` on Alpaca) | ETB direct or inverse fallback |
   | `PRE_MARKET` / `AFTER_HOURS` | `SMART` + `outsideRth=True` | `extended_hours=True` | Collared `LIMIT` (`35 bps`) | IBKR `STOP_LIMIT`; Alpaca `COLLARED_STOP_LIMIT_SUPERVISED` | ETB direct or inverse fallback |

### Confirmation

The encrypted `paper` profile powers `just paper-farm`. Each observation authenticates three distinct Alpaca accounts, checks their open orders and positions, and probes the IBKR paper socket on loopback port 4002. The runner records IBKR equity as unknown until a DU session supplies it. It reconciles entry and protective exit fills by broker activity ID, publishes the FINOS status and OTLP metrics, and stages fresh completed SIP bars in `tv_sota_pack/staged_scan_presets.json`. Each staged preset carries one share and requires manual confirmation.

On Windows, `scripts/run_live_paper_farm.ps1 -Mode start-loop -Observe` schedules the scan and reconciliation via zero-window `.venv/Scripts/pythonw.exe` running `scripts/paper_farm_loop_hidden.pyw` (`CREATE_NO_WINDOW = 0x08000000`, never flashing `pwsh.exe` consoles). The same command with `-ConfirmPaper` starts the paper execution worker. Both tasks run in the calling worktree. The worker uses Alpaca SIP and BOATS trades, RTH OTO stops and extended-session supervised limit exits. The November 25 paper histories include linked OTO stop replacements that tightened prices on each Alpaca account. The farm deployment flag requires a fill attributable to this worker on each Alpaca lane, a fresh supervision heartbeat and a reachable IBKR paper socket. Each Alpaca lane reports its own verification separately. A failed Dagster cost-calibration receipt holds new paper entries while the worker continues managing open positions. A farm with historical fills requires its calibration receipt. Extended-session protection depends on the worker and its market-data connection. ## Consequences

- **Positive:** Closes the predicted-vs-realized cost loop in exact `Decimal`, protects every extended-hours Alpaca and NautilusTrader order with collared `LIMIT`/`STOP_LIMIT` semantics, aligns `IBKR_DU_4002` rate limits to `3,000 rpm`, persists `paper_tca_fills` in isolated DuckDB ledgers, and exports official Prometheus/OTel telemetry with zero custom HTTP servers.
- **Negative:** Tight off-hours entry collars (`35`/`50 bps`) can leave fast-gapping orders unfilled (captured transparently as `opportunity_bps`), and live OTLP push requires `otel-collector-contrib` (`:4317`/`:4318`) running via `just resume`.

## Pros and Cons of the Options

### Option 1: Keep static cost assumptions

- Good, because zero implementation work is needed.
- Bad, because real slippage, off-hours rejects, and borrow drag silently invalidate `SHORT`-leg and extended-hours strategies.

### Option 2: Commercial TCA suite or external slippage framework

- Good, because vendor dashboards ship pre-built.
- Bad, because commercial tools fail the SPDX OSI firewall and add a duplicate execution data model.

### Option 3: Custom smart order router

- Good, because it appears to offer direct venue control.
- Bad, because retail workstations lack DMA and bespoke routers violate Zero Self-Invention.

### Option 4: Upstream-native `DuckDB`/`Polars` exact-`Decimal` TCA + broker-native 24/5 collared routing + OTel/Prometheus export

- Good, because it reuses pinned `NautilusTrader`/`alpaca-py`/DuckDB/Prometheus/OTel upstreams, passes all 6 acceptance tests offline, and reconciles directly into Dagster and 6-gate falsification.
- Bad, because broker API fill schemas must stay aligned whenever Alpaca or IBKR updates trade-update payloads.

### Self-Invention Lesson Learned & Mechanical Upstream Gate

- **Lesson learned:** Keeping this ADR `proposed` until every acceptance test and code defect (`engine.py` off-hours `MARKET`, `paper_farm.py` `1,000 rpm` and submission-vs-fill conflation) actually landed prevented paper-only documentation drift. Building TCA over `DuckDB` + `Decimal` + `Pydantic` v2 and metrics over `prometheus_client` + `opentelemetry` avoided bespoke TCA frameworks and prohibited HTTP servers.
- **Mechanical gates:** All 6 acceptance tests in `tests/test_core_engine.py` and `tests/test_live_automation.py`, `rules/zero_self_invention.yml` (`no-custom-dashboard-server`, `no-float-cast-in-risk`, `no-live-broker-endpoint`), `evals/formal_risk_z3.py`, `deptry .`, `gitleaks`, and `just check`.

### Compounding Layer Integration

- **`sim-backtest`:** Stores predicted cost in `MLflow`; re-falsification at measured paper cost links back to the source `run_id`.
- **`paper`:** `paper_lane_*.duckdb` persists `paper_tca_fills`; `PaperPerformanceAggregator` exports `mean_is_bps`, `p95_is_bps`, `total_borrow_fee_usd`, `extended_hours_protected_ratio`, and `submitted_vs_filled_ratio` into `FINOS`/`OpenBB`/`Grafana`/`OTel` ([ADR-0017](ADR-0017.md), [ADR-0021](ADR-0021.md)); `Dagster` asset `sim_vs_paper_parity_reconciliation` reconciles paper TCA against sim cost assumptions automatically.

- **`live`:** Stage-2 and Stage-4 dossiers under [ADR-0020](ADR-0020.md) consume reconciled per-leg TCA (`n >= 16` fills, `8/3` CPCV `>= 16` OOS paths / `cpcv_min_samples = 48`, realized cost within `2x`), keeping `live_execution_enabled = False` and `paper_only = True`.
