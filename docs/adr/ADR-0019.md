# ADR-0019: Execution Quality, Transaction Cost Analysis (TCA), Implementation Shortfall, Borrow-Fee Accounting & 24/5 Smart Order Routing (SOR)

> [!IMPORTANT]
> **Status: `proposed` (`E3`):** This ADR defines the target upstream-native TCA, borrow-fee accounting, and 24/5 route-selection policy. It remains `proposed` until the additive broker-fill schema, 5 TCA `pytest`/`Hypothesis` acceptance tests, `src/tier0_sota/engine.py:703` off-hours `LIMIT` entry remediation, and `src/tier0_sota/live/paper_farm.py:315` `IbkrPaperAdapter` RPM + fill-confirmation/extended-hours exit remediation land and pass CI.

## Context and Problem Statement

The Core Trading Philosophy only compounds if the cost assumptions inside the 6-gate falsification suite ([ADR-0016](ADR-0016.md)) hold on real fills. Today the repository *predicts* cost but does not *measure* realized execution quality:

- **Predicted cost only:** `run_nautilus_signal_backtest` and `build_sandbox_live_node` (`src/tier0_sota/engine.py`) use `MakerTakerFeeModel(0.0004, 0.0004)`, Gate 2 assumes `4.0 bps`/side (`1x`) and `8.0 bps`/side (`2x`), and `evaluate_hftbacktest_queue_markout` (`src/tier0_sota/research.py`) predicts passive `GTX` markout with `RiskAdverseQueueModel`. No step reconciles predictions against broker fills.
- **Paper ledger gaps:** `AlpacaPaperLane._record_order` (`src/tier0_sota/live/paper_farm.py`) writes `paper_wire_orders` without decision price, arrival quote, fill price, fill timestamp, fees, or borrow accrual; `pnl_usd` is written as `0.0`, and `counters["fills"]` increments at *submission* rather than broker fill confirmation.
- **Unmodeled borrow cost:** `select_short_or_inverse_fallback` verifies ETB (`easy_to_borrow is True`, `borrow_source == "alpaca_paper_asset"`) and falls back to `SOXS`/`SQQQ`, but neither path accrues short-borrow fees, HTB locate fees, or inverse-ETF drag.
- **24/5 routing parity defects (tracked for remediation):** Brokers accept only limit orders outside `RTH`, yet `SignalExecutionStrategy._submit_entry` (`src/tier0_sota/engine.py:703`) builds `order_factory.market(...)` in every session, `AlpacaPaperLane.submit_guarded_entry` attaches `OTO` stops only in `RTH`, and `IbkrPaperAdapter` (`src/tier0_sota/live/paper_farm.py:315`) sets `rate_budget_max_rpm=1000` vs the `3,000 rpm` `IBKR_PAPER_4002` profile.

## Decision Drivers

- **Close the predicted-vs-realized loop:** Reconcile every paper fill against assumed backtest costs (`MakerTakerFeeModel`, `1x`/`2x` gate costs, `hftbacktest` markout) so realized slippage can *falsify* a promoted strategy prior to Stage-4/5 ([ADR-0020](ADR-0020.md)).
- **Standard decomposition, not invented metrics:** Use Perold (1988) implementation shortfall (delay, execution/impact, explicit fees, borrow, opportunity cost) plus arrival-price, interval-VWAP, and forward mid markouts aligned with amended SEC Rule 605 (`2026-08-01`).
- **Native upstream data only:** Derive records from NautilusTrader v2 execution events, `alpaca-py` trade updates/account activities, IBKR `:4002` execution/commission reports, and SIP/BOATS quotes ([ADR-0013](ADR-0013.md)), joined via `DuckDB` `ASOF JOIN` / `Polars` `join_asof` in exact `Decimal`.
- **Exits always win:** Preserve `>= 10%` `ProtectiveExitRateBudget`, Rule-612 stop clamping (`<= 2.00%`), and the `-1.50%` latched fuse ([ADR-0005](ADR-0005.md)).
- **OSI-only, zero new dependencies:** Reuse pinned `uv.lock` packages exclusively.

## Considered Options

1. **Keep static cost assumptions (`4.0`/`8.0 bps`) and treat paper PnL as ground truth** — conceals slippage, adverse selection, borrow drag, and submission-vs-fill inflation.
2. **Adopt a commercial TCA suite or R/Zipline slippage package** — fails the SPDX OSI firewall or breaks `Sim == Paper == Live` parity with NautilusTrader.
3. **Build a custom smart order router / venue sweeper** — violates Zero Self-Invention and duplicates regulated broker routers (`IBKR SMART`, Alpaca/BOATS).
4. **Upstream-native TCA + exact `Decimal` Perold IS + broker-native 24/5 route-selection policy (chosen)**.

## Decision Outcome

Adopt Option 4 as the proposed target design extending [ADR-0007](ADR-0007.md), [ADR-0009](ADR-0009.md), [ADR-0013](ADR-0013.md), [ADR-0014](ADR-0014.md), [ADR-0015](ADR-0015.md), and [ADR-0016](ADR-0016.md):

1. **Execution-quality records from native upstream events only:** NautilusTrader v2 `OrderFilled` + `generate_fills_report()`, `alpaca-py` `TradingStream` `trade_updates` / `get_account_activities`, and IBKR `:4002` `FillReport`. Add an additive `DuckDB` broker-fill table (`DECIMAL(18,6)` / `pl.Decimal`, zero `float`) keyed by `broker_order_id`, counting `counters["fills"]` strictly on broker fill confirmation.
2. **Perold implementation shortfall (`s = +1` buy / `-1` sell, bps of decision notional):**
   - `delay_bps = s * (arrival_mid - decision_mid) / decision_mid * 1e4` (decision at causal `t_ns + 60s`, [ADR-0003](ADR-0003.md)).
   - `execution_bps = s * (VWAP_fill - arrival_mid) / decision_mid * 1e4`; `explicit_bps = (commission + regulatory_fees) / decision_notional * 1e4`; `borrow_bps`; `opportunity_bps = s * (horizon_mid - decision_mid) * unfilled_qty / decision_notional * 1e4`.
   - Benchmarks: arrival price, interval VWAP, and forward mid markouts at `1 s`, `5 s`, `60 s`, `300 s` via `DuckDB` `ASOF JOIN` / `Polars` `join_asof` with staleness drop (never imputing stale quotes), reported as median and p90 by `account x lane_id x session x side x route`.
3. **Predicted-vs-realized reconciliation (`MIN_CPCV_SAMPLES = 16` per independent `LONG`/`SHORT` leg):**
   - Realized per-side cost `<= 4.0 bps` (`1x`) keeps the backtest valid; `(4.0, 8.0]` bps makes `2x` binding; `> 8.0 bps` or realized 60 s markout `< -20.0 bps` falsifies the cost assumption, demoting the lane to `sim-backtest` for re-falsification at measured cost.
4. **Shadow-accrued exact `Decimal` borrow-fee & inverse-drag accounting:** `daily_fee = round_lot_up(qty) * prior_close * annual_rate / 360` (calendar-day accrual, Friday = 3 days; Alpaca ETB = `0`; fail-closed inverse ETF fallback charges expense ratio + daily leverage-reset drag as `borrow_bps`; pre-open ETB->HTB cancels recorded as `opportunity_bps`).
5. **24/5 route-selection policy (picking strictly among broker-native routers):**

   | Session (ET) | `IBKR_DU_4002` route | `ALPACA_PA1..PA3` route | Entry order | Protective exit | Opening shorts |
   |---|---|---|---|---|---|
   | `RTH` 09:30–16:00 | `SMART` | Alpaca default routing | Marketable `LIMIT` (collared) | Native `STOP_MARKET` (`OTO` on Alpaca) | ETB direct or inverse fallback |
   | `PRE_MARKET` / `AFTER_HOURS` | `SMART` + `outsideRth=True` | `extended_hours=True` | `LIMIT` only (`35 bps` collar) | IBKR native `STOP_LIMIT`; Alpaca via `OrderEmulator`-triggered collared `LIMIT` | ETB direct or inverse fallback |
   | `OVERNIGHT` 20:00–04:00 | `SMART` + `includeOvernight` or `OVERNIGHT` | BOATS via `extended_hours=True` + `overnight_tradable` (`supports_extended_overnight_24x5 = False` on `ALPACA_PAPER_200`) | `LIMIT` only (`50 bps` collar) | Emulated collared `LIMIT` | Blocked on Alpaca (already enforced) |

   Remediate `engine.py:703` (`MARKET` outside `RTH`), `paper_farm.py:315` (`1000` -> `3000` rpm), and Alpaca off-hours stop supervision in the implementation PR that promotes this ADR from `proposed` to `accepted`. Live profiles and live ports `4001/7496/8798/8796` remain hard-refused.

## Consequences

- **Positive:** Defines an OSI-clean, zero-new-dependency path to close the predicted-vs-realized cost loop in exact `Decimal` and transparently flags existing routing/ledger gaps (`status: proposed`) rather than masking unimplemented work as `accepted`.
- **Negative:** Requires additive broker-fill/IS schema updates in `paper_farm.py`, remediation of `engine.py:703` / `paper_farm.py:315`, and 5 new pytest tests before Stage-2/Stage-4 TCA reconciliation passes `n >= 16`.

## Pros and Cons of the Options

### Option 1: Keep static cost assumptions

- Good, because zero implementation work is needed.
- Bad, because real slippage and borrow drag silently invalidate `SHORT`-leg and off-hours strategies.

### Option 2: Commercial TCA suite or external slippage framework

- Good, because vendor dashboards ship pre-built.
- Bad, because commercial tools fail the SPDX OSI firewall and add a duplicate execution data model.

### Option 3: Custom smart order router

- Good, because it appears to offer venue control.
- Bad, because retail workstations lack DMA and bespoke routers violate Zero Self-Invention.

### Option 4: Upstream-native `DuckDB`/`Polars` TCA + broker-native 24/5 route policy

- Good, because it adds zero new dependencies, reuses native `NautilusTrader`/`alpaca-py`/IBKR events in exact `Decimal`, and feeds directly into 6-gate re-falsification.
- Bad, because it requires remediating `engine.py:703` and `paper_farm.py` before transitioning to `accepted`.

### Self-Invention Lesson Learned & Mechanical Upstream Gate

- **Lesson learned:** Cost realism decayed silently because the repository only had *predicted* costs and counted submissions as fills; meanwhile marking an unimplemented design `Accepted` risked masking missing tests. Setting `status: proposed` (`E3`) with explicit graduation criteria keeps the ADR corpus 100% truthful while banning custom "TCA engines" or bespoke venue routers.
- **Mechanical gates:** Existing `rules/zero_self_invention.yml`, `risk.py` SHA-256 + `evals/formal_risk_z3.py`, `deptry .`, `gitleaks`, plus the 5 pending TCA pytest acceptance tests listed under *Confirmation*.

### Compounding Layer Integration

- **`sim-backtest`:** Stores predicted cost in `MLflow`; re-falsification at measured paper cost links back to the source `run_id`.
- **`paper`:** `paper_lane_*.duckdb` gains broker-fill/IS tables; `PaperPerformanceAggregator` exports `median_is_bps`, `p90_is_bps`, `markout_60s_bps`, `borrow_bps`, `route_rejects`, and `fills_confirmed` into the official hosting and `L10` UI stack ([ADR-0017](ADR-0017.md), [ADR-0021](ADR-0021.md)).

- **`live`:** Stage-2 and Stage-4 dossiers under [ADR-0020](ADR-0020.md) require reconciled TCA per leg (`n >= 16`, realized cost within `2x`), while `live_execution_enabled = False` and `paper_only = True`.
