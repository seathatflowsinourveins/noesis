# ADR-0011: Official Upstream L10 UI & 13-Portal Observability Stack (otel-collector-contrib + Caddy)

> [!NOTE]
> **Superseded by [ADR-0017](ADR-0017.md) and [ADR-0021](ADR-0021.md):** [ADR-0017](ADR-0017.md) superseded the hosting/observability portion with the verified 15-portal WSL2 `Noesis-SOTA` + Docker Compose stack and automated `just resume` recovery; [ADR-0021](ADR-0021.md) superseded the `L10` institutional UI, trading cockpit, and multimodal workbench portion. The underlying `otel-collector-contrib` + `caddy` zero-shim decision remains in force across both successors.

## Context and Problem Statement

Custom-written HTML/JS dashboards (`FastAPI`/`Flask`/`Streamlit`/`Dash`) and inline-Python Docker/systemd shims (`python -m http.server`, ad-hoc inline telemetry scripts) violate Zero Self-Invention and duplicate observability and static-serving infrastructure already delivered cleanly by official upstream `L6` and `L10` platforms.

## Decision Drivers

- Maintain zero hand-written HTML/JS dashboards in `src/`/`scripts/` and zero inline-Python telemetry or HTTP server shims in `docker/` or WSL2 systemd units.
- Serve real `otelcol_*` Prometheus metrics on `:9464/metrics` via official upstream `otel/opentelemetry-collector-contrib` (`docker/otel-collector-config.yaml`) and serve tearsheets on `:8793` via official upstream `caddy` (`caddy file-server`).
- Provide full `L10` (`Institutional UI & Visual Analytics`) coverage (`finos-workspace`, `OpenBB`, `perspective`, `lightweight-charts`, `ag-grid-community`) strictly via declarative JSON exports.

## Considered Options

1. **Custom FastAPI/HTML dashboards or inline-Python telemetry & `http.server` shims** — violates Zero Self-Invention and `no-custom-dashboard-server`.
2. **Official `L6` + `L10` 13-Portal Upstream Stack** managed via `docker/compose.sota.yml` (`otel/opentelemetry-collector-contrib` + `caddy` + `prom/prometheus` + `grafana/grafana` + `MLflow` + `Dagster` + `Optuna` + `Inspect` + `Zensical` + `XERJ` + `FINOS` + `OpenBB`).

## Decision Outcome

Adopt Option 2 across the original 13 loopback portals (`127.0.0.1`), subsequently expanded to 15 portals under [ADR-0017](ADR-0017.md) and specialized for `L10` UI under [ADR-0021](ADR-0021.md):

- **`L10` Visual Analytics:** FINOS Workspace (`:1420`, `perspective` + `ag-grid-community`), FINOS API (`:8000`), OpenBB (`:6900`), official `caddy` Tearsheets (`:8793`), DuckDB SQL UI (`:4213`).
- **`L6` Orchestration & Experiments:** Dagster (`:3000`, `tier0_sota.definitions`), MLflow (`:5000`), Optuna Dashboard (`:8080`), Inspect AI (`:7575`).
- **`L6` Metrics, Memory & Docs:** Grafana (`:3001`), Prometheus (`:9090`), official `otel/opentelemetry-collector-contrib` (`:9464/metrics`, OTLP `:4317`/`:4318`), XERJ (`:9200`), Zensical ADR Portal (`:8010`).

## Consequences

- **Positive:** Replaced inline-Python metrics and HTTP server shims with official upstream `otel/opentelemetry-collector-contrib` (`:9464`) and `caddy` (`:8793`) containers.
- **Negative:** The 13-portal inventory and manual startup framing drifted once DuckDB UI (`:4213`), OpenBB (`:6900`), OTel health (`:13133`), `just resume`, and `L10` plugin governance landed, prompting supersession by [ADR-0017](ADR-0017.md) and [ADR-0021](ADR-0021.md).

## Pros and Cons of the Options

### Option 1: Custom FastAPI/HTML dashboards or inline-Python shims

- Good, because ad-hoc endpoints spin up quickly.
- Bad, because they introduce XSS/CSP risk, lack Prometheus/OTel semantics, and violate `no-custom-dashboard-server`.

### Option 2: Official `L6` + `L10` upstream containers (`otel-collector-contrib` + `caddy`)

- Good, because all dashboards and telemetry run on battle-tested upstream images with zero bespoke web assets.
- Bad, because the 13-portal framing quickly outgrew its original count, requiring [ADR-0017](ADR-0017.md) and [ADR-0021](ADR-0021.md).

- **Lesson Learned:** Earlier Docker compose and systemd units relied on an inline-Python fake Prometheus metrics server and `python -m http.server` for `:8793`. Both inline shims were permanently replaced with official `otel/opentelemetry-collector-contrib` + `docker/otel-collector-config.yaml` and `caddy file-server`.
- **Mechanical Upstream Gates:** `rules/zero_self_invention.yml` (`no-custom-dashboard-server`), `.pre-commit-config.yaml` (`no-handwritten-web-assets`), `uv run --no-sync zensical build --clean --strict`, `trivy fs`, `tests/test_grand_reset_kit.py`, and `scripts/grand_reset/verify_grand_reset.ps1` (historically `hosted_portals_13`, now `hosted_portals_15` under [ADR-0017](ADR-0017.md)).
