# ADR-0011: Official Upstream `L10` UI & 13-Portal Observability Stack (`otel-collector-contrib` + `Caddy`)

- **Status:** Superseded by [ADR-0017](ADR-0017.md)
- **Date:** 2026-11-26
- **Evidence Grade:** E4
- **Sole Source of Truth:** SOTA upstream convergence per Core Trading Philosophy

## Context and Problem Statement

Custom-written HTML/JS dashboards (`FastAPI`/`Flask`/`Streamlit`/`Dash`) and inline-Python Docker/systemd shims (`python -m http.server`, ad-hoc inline telemetry scripts) violate Zero Self-Invention and duplicate observability and static-serving infrastructure already delivered cleanly by official upstream `L6` and `L10` platforms.

## Decision Drivers

- Maintain zero hand-written HTML/JS dashboards in `src/`/`scripts/` and zero inline-Python telemetry or HTTP server shims in `docker/` or WSL2 systemd units.
- Serve real `otelcol_*` Prometheus metrics on `:9464/metrics` via official upstream `otel/opentelemetry-collector-contrib` (`docker/otel-collector-config.yaml`) and serve tearsheets on `:8793` via official upstream `caddy` (`caddy file-server`).
- Provide full `L10` (`Institutional UI & Visual Analytics`) coverage (`finos-workspace`, `OpenBB`, `perspective`, `lightweight-charts`, `ag-grid`) strictly via declarative JSON exports.

## Considered Options

1. **Custom FastAPI/HTML dashboards or inline-Python telemetry & `http.server` shims** — violates Zero Self-Invention and `no-custom-dashboard-server`.
2. **Official `L6` + `L10` 13-Portal Upstream Stack** managed via `docker/compose.sota.yml` (`otel/opentelemetry-collector-contrib` + `caddy` + `prom/prometheus` + `grafana/grafana` + `MLflow` + `Dagster` + `Optuna` + `Inspect` + `Zensical` + `XERJ` + `FINOS` + `OpenBB`).

## Decision Outcome

Adopt Option 2 across all 13 loopback portals (`127.0.0.1`):
- **`L10` Visual Analytics:** FINOS Workspace (`:1420`, `perspective` + `ag-grid`), FINOS API (`:8000`), OpenBB (`:6900`), official `caddy` Tearsheets (`:8793`), DuckDB SQL UI (`:4213`).
- **`L6` Orchestration & Experiments:** Dagster (`:3000`, `tier0_sota.definitions`), MLflow (`:5000`), Optuna Dashboard (`:8080`), Inspect AI (`:7575`).
- **`L6` Metrics, Memory & Docs:** Grafana (`:3001`), Prometheus (`:9090`), official `otel/opentelemetry-collector-contrib` (`:9464/metrics`, OTLP `:4317`/`:4318`), XERJ (`:9200`), Zensical ADR Portal (`:8010`).

## Consequences

- **Positive:** Replaced inline-Python metrics and HTTP server shims with official upstream `otel/opentelemetry-collector-contrib` (`:9464`) and `caddy` (`:8793`) containers.
- **Negative:** The 13-portal inventory and manual startup framing drifted once DuckDB UI (`:4213`), OpenBB (`:6900`), OTel health (`:13133`), and `just resume` landed, prompting supersession by [ADR-0017](ADR-0017.md).

### Upstream Evidence & Official Directives

- **Official Upstream Images & Docs:** `otel/opentelemetry-collector-contrib`, `caddy` (`caddyserver/caddy`), `prom/prometheus`, `grafana/grafana`, `dagster-io/dagster`, `mlflow/mlflow`, `optuna/optuna-dashboard`, `zensical/zensical`, `openbq-org/finos-workspace`, `OpenBB-finance/OpenBB`, `finos/perspective`, `tradingview/lightweight-charts`, `ag-grid/ag-grid`.

### Self-Invention Lesson Learned & Mechanical Upstream Gate

- **Lesson Learned:** Earlier Docker compose and systemd units relied on an inline-Python fake Prometheus metrics server and `python -m http.server` for `:8793`. Both inline shims were permanently replaced with official `otel/opentelemetry-collector-contrib` + `docker/otel-collector-config.yaml` and `caddy file-server`.
- **Mechanical Upstream Gates:** `rules/zero_self_invention.yml` (`no-custom-dashboard-server`), `.pre-commit-config.yaml` (`no-handwritten-web-assets`), `uv run --no-sync zensical build --clean --strict` (`.github/workflows/docs.yml`), `trivy fs`, `tests/test_grand_reset_kit.py` (`test_docker_compose_sota_yaml_mounts_and_no_live_ports`), and `scripts/grand_reset/verify_grand_reset.ps1` (`hosted_portals_13`).

### Compounding Layer Integration

- Renders live compounding telemetry across all 4 lanes: `MLflow` (`sim-backtest`), `FINOS`/`OpenBB`/`DuckDB UI`/`Grafana`/`OTel` (`paper`), `Caddy` tearsheets (`sim-backtest` + `half-auto-tv`), and `Zensical` + `XERJ` (evolving ADRs & architectural lessons).

### Living Evolution & Supersession Policy

- Superseded by [ADR-0017](ADR-0017.md), which restates this stack as the verified 15-portal engine (adds OTel health `:13133`, DuckDB SQL UI and OpenBB as systemd-hosted portals, OmniRoute gating, the 5-asset Dagster reflection schedule, and automated post-restart `just resume` recovery). This record is kept as the historical 13-portal snapshot; the official-upstream `otel-collector-contrib` + `caddy` decision itself remains in force.
