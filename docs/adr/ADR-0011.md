# ADR-0011: Official Upstream 13-Portal Observability & Research Stack

- **Status:** Accepted
- **Date:** 2026-11-25
- **Evidence Grade:** E4

## Context and Problem Statement

Custom-written HTML/JS dashboards (`FastAPI`/`Flask`/`Streamlit`/`Dash`) accumulate frontend maintenance debt and duplicate telemetry already served better by official upstream platforms.

## Decision Drivers

- Zero hand-written HTML/JS dashboards inside `src/tier0_sota/` or `scripts/`.
- Loopback-bound (`127.0.0.1`) research, pipeline, metrics, tearsheet, memory, and ADR portals.
- Declarative JSON exports (`OpenBB` / `FINOS`, `Prometheus`, `OTel`, `MLflow`, `Zensical`).

## Considered Options

1. **Custom FastAPI + React/HTML dashboard servers** — violates `no-custom-dashboard-server` AST rule and bloats the repo.
2. **Official 13-Portal Upstream Stack** managed via `docker/compose.sota.yml` and declarative JSON feeds.

## Decision Outcome

Adopt Option 2 across all 13 loopback portals:
- **Interactive Analytics:** FINOS Workspace (`:1420`), FINOS API (`:8000`), OpenBB (`:6900`), Nautilus/ML4T Tearsheets (`:8793`), DuckDB SQL UI.
- **Orchestration & Experiments:** Dagster (`:3000`), MLflow (`:5000`), Optuna Dashboard (`:8080`), Inspect AI (`:7575`).
- **Metrics, Memory & Docs:** Grafana (`:3001`), Prometheus (`:9090`), OpenTelemetry Prometheus exporter (`:9464`), XERJ (`:9200`), Zensical ADR Portal (`:8010`).

### Consequences

- **Positive:** Institutional observability with zero custom web frontend code in the repository.
- **Negative:** Full portal matrix depends on the local Docker Compose stack (`docker/compose.sota.yml`).
