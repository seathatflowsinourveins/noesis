# ADR-0010: ToU-Compliant TradingView Pine v6 & Draft 2020-12 Half-Auto Bridge

- **Status:** Accepted
- **Date:** 2026-11-25
- **Evidence Grade:** E4

## Context and Problem Statement

TradingView provides rich charting and visual feedback for Half-Automation, but browser automation, CDP debug-port attachment (`:9223`), repainting scripts, or unvalidated alert payloads violate TradingView ToU and fail-closed risk invariants.

## Decision Drivers

- 100% ToU-compliant display-only Pine v6 indicators (`barstate.isconfirmed`, `gaps=barmerge.gaps_off`, `lookahead=barmerge.lookahead_off`, zero CDP `:9223`).
- Fail-closed Draft 2020-12 JSON schema bridge enforcing `qty=1`, `semi_auto_confirmed=false`, Rule-612 inward stops (`<= 2.00%`), XNYS session parity, and borrow gates.
- Operator ticket & watchlist generation aligned with `engine.py` and `risk.py`.

## Considered Options

1. **CDP browser automation or unvalidated webhook relays** — violates ToU and risks unintended live orders.
2. **Display-only Pine v6 (`tier0_omni_sota_24x5.pine` + `tier0_market_regime.pine`) + Draft 2020-12 `tv/bridge.py` + Half-Auto `tv/tickets.py` + `scripts/tv_console.ps1`**.

## Decision Outcome

Adopt Option 2. Both Pine v6 indicators mirror the `3x4` trailing matrix, 4-tier progressive R-lock, `fast_sell_climax` auto-reverse, and `60s` re-entry using valid Pine v6 colors and leading-zero JSON formatting (`tier0.tv-alert.v1`). `tv/bridge.py` validates every alert against `schema_v1.json`, `risk.py`, `XNYS` sessions, and ETB borrow evidence before atomically staging (`semi_auto_confirmed=false`). `tv/tickets.py` produces extreme-mover tickets with `lock_at_1r`, `lock_at_2r`, `fast_sell_rev_trigger`, and grouped TradingView watchlists.

### Consequences

- **Positive:** Full TradingView visual & Half-Auto parity with zero ToU exposure and zero unconfirmed auto-submission.
- **Negative:** Operator manually imports watchlists/Pine scripts via `scripts/tv_console.ps1` clipboard helpers.
