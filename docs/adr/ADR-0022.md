# ADR-0022: SOTA-Enhanced Antigravity (AGY 2.0) Native Workspace Architecture, Zero-Copy Disk-Z Skills Discovery & Official Orca Hook Preservation

## Context and Problem Statement

Running Antigravity (`AGY 2.0`) alongside `Orca`, `Claude Code`, `Codex`, `Gemini CLI`, and `OpenCode` on `Z:\noesis` revealed three recurring configuration defects in earlier Grand-Reset scripts (`scripts/grand_reset/00_clean_disk_z_and_agy_reset.ps1` and `02_runtimes_agy_orca_setup.ps1`):

1. **Duplicate Disk-C Skill Copies:** Copying all 46 standalone skills from `Z:\noesis\.claude\skills` into `~/.gemini/config/skills/` and `~/.gemini/skills/` duplicated hundreds of helper files on Disk-C and drifted whenever `UPSTREAM_SKILLS_LOCK.json` updated.
2. **Blind Removal of Official Orca Status Hooks:** Stripping the entire `"hooks"` object when writing `~/.gemini/settings.json` risked clobbering official upstream Orca status hooks (`~/.orca/agent-hooks/*.cmd`), violating [ADR-0012](ADR-0012.md) and `LLM_HARNESS_MANIFEST.json` (`hooks_policy`).
3. **Brittle AGY MCP Paths & Missing Env Propagation:** Using `uv run --directory` wrappers or hardcoded versioned `C:` paths in `~/.gemini/config/mcp_config.json` broke direct binary resolution, while omitting dynamic `EDGAR_IDENTITY` propagation caused `edgartools-mcp.exe` startup failures.

## Decision Drivers

- **Zero-Copy Disk-Z Skills Discovery:** Configure workspace (`.agents/skills.json`) and user-level (`~/.gemini/config/skills.json`) skill discovery to reference `.claude/skills` / `Z:/noesis/.claude/skills` directly without copying skill trees onto Disk-C for AGY.
- **Official Orca Hook Preservation:** Filter out any self-invented/non-Orca hook entries while preserving official upstream `~/.orca/agent-hooks/*.cmd` hooks in `~/.gemini/settings.json` and `~/.gemini/config/hooks.json`.
- **Clean Native MCP Binaries & Zero PII in Repo:** Resolve `codebase-memory-mcp` and `xerj` cleanly via `PATH`, point `nautilus-engine` and `edgartools` directly to `Z:/noesis/.venv/Scripts/{python.exe,edgartools-mcp.exe}`, and propagate `EDGAR_IDENTITY` dynamically from User/Machine/Process env (or encrypted `fnox`, [ADR-0023](ADR-0023.md)) without committing PII.
- **Mechanical Preflight & Test Parity:** Keep `scripts/preflight_resume.{ps1,sh}` at 13 always-on gates and verify `.agents/skills.json` automatically in `tests/test_grand_reset_kit.py`.

## Considered Options

1. **Continue copying 46 skill folders into `~/.gemini/config/skills/` and stripping all `"hooks"` from `~/.gemini/settings.json`** — wastes Disk-C space, creates stale skill copies, and breaks Orca agent status tracking.
2. **Zero-copy `.agents/skills.json` + `~/.gemini/config/skills.json` pointing to `.claude/skills` (`Z:/noesis/.claude/skills`), surgical Orca hook preservation, and clean native AGY MCP paths with dynamic `EDGAR_IDENTITY` propagation (chosen)**.

## Decision Outcome

Adopt **Option 2** across `.agents/skills.json`, `scripts/grand_reset/00_clean_disk_z_and_agy_reset.ps1`, `02_runtimes_agy_orca_setup.ps1`, and `scripts/preflight_resume.{ps1,sh}`, paired with an explicit Windows-primary / WSL2-companion Antigravity topology:

- **Workspace & User Zero-Copy Skills Discovery:** Commit `.agents/skills.json` (`{"entries": [{"path": ".claude/skills"}]}`) to load all `46/46` skills inside `noesis`, write `~/.gemini/config/skills.json` with `include_only` scoped to the 7-skill Governance Spine (`orca-cli`, `orca-per-workspace-env`, `orchestration`, `tier0-code-intel-and-gates`, `tier0-quant-falsification`, `tier0-upstream-convergence`, `verification-before-completion`) in `00`, `01_wsl_bootstrap.sh`, and `02` (reducing outside-of-project custom skill description tokens by `-79.22%` `cl100k`), and stop copying skills into `~/.gemini/config/skills/` (retaining Claude/Codex sync in `02`).
- **Orca Hook Preservation & `context.fileName` Restoration:** When updating Windows `~/.gemini/settings.json`, preserve official `~/.orca/agent-hooks/` hook entries while removing any custom/non-Orca hooks, preserve `"context": {"fileName": ["AGENTS.md", "GEMINI.md"]}` so Gemini CLI / AGY consistently resolve canonical `AGENTS.md`, and never alter `~/.gemini/config/hooks.json` Orca entries.
- **Native AGY MCP Config, Workspace Attachment & Preflight Gate #8:** In `02_runtimes_agy_orca_setup.ps1`, emit `codebase-memory-mcp`, `xerj`, `$RepoRootSlash/.venv/Scripts/python.exe` (`nautilus-engine`), and `$RepoRootSlash/.venv/Scripts/edgartools-mcp.exe` (`edgartools`) with dynamic `EDGAR_IDENTITY` propagation (matching the 4-server typed MCP architecture in [ADR-0025](ADR-0025.md)). On Windows, `scripts/preflight_resume.ps1` (`agy_native_mcp_config`) validates `noesis` in either `command` or `args` plus `~/.gemini/config/skills.json`; on WSL2, `scripts/preflight_resume.sh` Gate #8 checks `~/.gemini/config/mcp_config.json` first (falling back to 5/5 native `uv` repo parity when absent), alongside `config/projects/` workspace attachment (`just open-agy` / `just open-agy-wsl`).

### Precedence-Ordered AGY Context Load Manifest

1. **Workspace SSOT & Skills:** Canonical `AGENTS.md` + `.agents/skills.json` -> `46/46` SHA-256-locked standalone skills in `.claude/skills/` (`UPSTREAM_SKILLS_LOCK.json`).
2. **Global Charter & Zero-Copy Skills:** `~/.gemini/GEMINI.md` (`8/8` cross-OS SHA-256 `9fa037355c3942201e3c0813acaa7b01c590e6294cd5e85787ae1bdcef55a7b8`) + `~/.gemini/config/skills.json` (zero-copy pointer to `Z:/noesis/.claude/skills` on Windows and `/mnt/z/noesis/.claude/skills` on WSL2).
3. **Native MCP Servers (`4`):** `codebase-memory`, `xerj`, `nautilus-engine`, `edgartools` declared in `~/.gemini/config/mcp_config.json` (zero `bash -c` wrappers, dynamic `EDGAR_IDENTITY`).
4. **Upstream Hooks Only:** Official Orca status hooks (`~/.orca/agent-hooks/*`) preserved exclusively; `hooks_zero = True` for all custom repository/runtime hooks.
5. **Operator Workstation Hygiene (operator-verified outside CI):** Keep minimal AGY plugins (`swarm` plugin only), `0` legacy global workflows, and `0` leaked global provider API keys.

## Consequences

- **Positive:** Eliminates Disk-C skill duplication for AGY 2.0, preserves live Orca agent status hooks across Grand-Reset runs, resolves AGY MCP binaries directly inside `Z:\noesis\.venv` (and ext4 `~/noesis/.venv` on WSL2), gives operators native NTFS/Win32 speed as primary alongside a parity-locked Linux WSL2 companion, and avoids PII leakage in tracked files.
- **Negative:** Requires Antigravity (`AGY 2.0`) to support `.agents/skills.json` / `~/.gemini/config/skills.json` directory-entry manifests, relies on `codebase-memory-mcp` / `xerj` on `PATH`, and WSL2 Linux Desktop GUI rendering depends on WSLg availability (while `agy` CLI operates headlessly without WSLg).

## Pros and Cons of the Options

### Option 1: Copy 46 skills to Disk-C + strip all `"hooks"`

- Good, because legacy tools that ignore pointer manifests see local copies.
- Bad, because skill copies bloat Disk-C, drift on lock updates, and stripping `"hooks"` breaks Orca status reporting.

### Option 2: Zero-copy `.agents/skills.json` + surgical Orca hook preservation + native MCP binaries

- Good, because one SHA-256-locked `.claude/skills/` tree serves every runtime with zero copy drift and intact Orca status hooks.
- Bad, because host-level `~/.gemini/config/` synchronization still runs through `scripts/grand_reset/02_runtimes_agy_orca_setup.ps1` and `01_wsl_bootstrap.sh`.

## More Information

### Upstream Evidence & Empirical Benchmarks

- **AAIF & Antigravity Discovery:** `.agents/skills.json` and `~/.gemini/config/skills.json` point directly to the 46 SHA-256-locked skills in `.claude/skills/` (`UPSTREAM_SKILLS_LOCK.json`), verified `46/46` by `tests/test_architecture_manifest.py` across all 6 runtimes (`Antigravity`, `Orca` with WSL2-safe `scripts/orca_account_failover.py` refusing `/usr/bin/orca`, `Codex` `multi_agent_v2 = true`, `Claude Code`, `OpenCode`, `Gemini CLI`).
- **Orca Hook Compatibility:** Official `~/.orca/agent-hooks/*.cmd` status hooks remain intact alongside `hooks_zero = True` for custom repo hooks (`LLM_HARNESS_MANIFEST.json` `official_upstream_orca_hooks_only: true`).
- **Grand-Reset & Preflight Verification:** Both `00_clean_disk_z_and_agy_reset.ps1` and `02_runtimes_agy_orca_setup.ps1` pass PowerShell AST parsing and `-DryRun`, while `scripts/preflight_resume.{ps1,sh}` pass `13/13` always-on gates.

### Self-Invention Lesson Learned & Mechanical Upstream Gate

- **Lesson Learned:** Blindly deleting `"hooks"`, cloning 46 skill directories onto Disk-C, and hardcoding fragile line counts (such as citing `AGENTS.md` line count in prose) created avoidable churn and drift. Native directory-pointer manifests, targeted hook filtering, and automated preflight verification replace all three.
- **Mechanical Upstream Gates:** `tests/test_grand_reset_kit.py`, `scripts/preflight_resume.{ps1,sh}` (`agy_native_mcp_config`), and `gitleaks` (blocking hardcoded personal `EDGAR_IDENTITY`).

### Compounding Layer Integration

- Ensures Antigravity and Orca multi-agent sessions across all 4 compounding harness lanes (`sim-backtest`, `paper`, `half-auto-tv`, `live`) share the exact 46-skill catalog, 4 native MCP servers, encrypted `fnox` profiles ([ADR-0023](ADR-0023.md)), and live Orca coordination status without Disk-C drift.

- Governed by [ADR-0024](ADR-0024.md): amend or supersede as Antigravity (`AGY 2.0+`) or Orca discovery conventions evolve, preserving zero custom repo hooks, `src/tier0_sota/risk.py` SHA-256 (`ad8071dcd4196c4c529c02107114ebfdda6692bc9d7c220031f1b19ea3e4d847`), and live broker port isolation (`:4001`, `:7496`, `:8798`, `:8796`).
