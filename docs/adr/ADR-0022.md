# ADR-0022: SOTA-Enhanced Antigravity (AGY 2.0) Native Workspace Architecture, Zero-Copy Disk-Z Skills Discovery & Official Orca Hook Preservation

- **Status:** Accepted
- **Date:** 2026-11-26
- **Evidence Grade:** E4
- **Sole Source of Truth:** SOTA upstream convergence per Core Trading Philosophy
- **Related:** [ADR-0012](ADR-0012.md) (AAIF `AGENTS.md` SSOT & Grand-Reset), [ADR-0017](ADR-0017.md) (Native Workstation Hosting & 15-Portal Stack), [ADR-0018](ADR-0018.md) (Multi-Model Agentic Harness & OmniRoute)

## Context and Problem Statement

Running Antigravity (`AGY 2.0`) alongside `Orca`, `Claude Code`, `Codex`, `Gemini CLI`, and `OpenCode` on `Z:\noesis` revealed three recurring configuration defects in earlier Grand-Reset scripts (`scripts/grand_reset/00_clean_disk_z_and_agy_reset.ps1` and `02_runtimes_agy_orca_setup.ps1`):

1. **Duplicate Disk-C Skill Copies:** Copying all 46 standalone skills from `Z:\noesis\.claude\skills` into `~/.gemini/config/skills/` and `~/.gemini/skills/` duplicated hundreds of helper files on Disk-C and drifted whenever `UPSTREAM_SKILLS_LOCK.json` updated.
2. **Blind Removal of Official Orca Status Hooks:** Stripping the entire `"hooks"` object when writing `~/.gemini/settings.json` risked clobbering official upstream Orca status hooks (`~/.orca/agent-hooks/*.cmd`), violating [ADR-0012](ADR-0012.md) and `LLM_HARNESS_MANIFEST.json` (`hooks_policy`).
3. **Brittle AGY MCP Paths & Missing Env Propagation:** Using `uv run --directory` wrappers or hardcoded versioned `C:` paths in `~/.gemini/config/mcp_config.json` broke direct binary resolution, while omitting dynamic `EDGAR_IDENTITY` propagation caused `edgartools-mcp.exe` startup failures when launched without inherited user environment variables.

## Decision Drivers

- **Zero-Copy Disk-Z Skills Discovery:** Configure workspace (`.agents/skills.json`) and user-level (`~/.gemini/config/skills.json`) skill discovery to reference `.claude/skills` / `Z:/noesis/.claude/skills` directly without copying skill trees onto Disk-C for AGY.
- **Official Orca Hook Preservation:** Filter out any self-invented/non-Orca hook entries while preserving official upstream `~/.orca/agent-hooks/*.cmd` hooks in `~/.gemini/settings.json` and `~/.gemini/config/hooks.json`.
- **Clean Native MCP Binaries & Zero PII in Repo:** Resolve `codebase-memory-mcp` and `xerj` cleanly via PATH, point `nautilus-engine` and `edgartools` directly to `Z:/noesis/.venv/Scripts/{python.exe,edgartools-mcp.exe}`, and propagate `EDGAR_IDENTITY` dynamically from User/Machine/Process env without ever committing PII.
- **Mechanical Preflight & Test Parity:** Keep `scripts/preflight_resume.{ps1,sh}` at 13 always-on gates (`-CleanLegacyLocked` opt-in 14th gate on Windows) and verify `.agents/skills.json` and `ADR-0022.md` automatically in `tests/test_grand_reset_kit.py`.

## Considered Options

1. **Continue copying 46 skill folders into `~/.gemini/config/skills/` and stripping all `"hooks"` from `~/.gemini/settings.json`** — wastes Disk-C space, creates stale skill copies, and breaks Orca agent status tracking.
2. **Zero-copy `.agents/skills.json` + `~/.gemini/config/skills.json` pointing to `.claude/skills` (`Z:/noesis/.claude/skills`), surgical Orca hook preservation, and clean native AGY MCP paths with dynamic `EDGAR_IDENTITY` propagation**.

## Decision Outcome

Adopt **Option 2** across `.agents/skills.json`, `scripts/grand_reset/00_clean_disk_z_and_agy_reset.ps1`, `02_runtimes_agy_orca_setup.ps1`, and `scripts/preflight_resume.{ps1,sh}`, paired with an explicit Windows-primary / WSL2-companion Antigravity topology and precedence-ordered context manifest:

- **Workspace & User Zero-Copy Skills Discovery:** Commit `.agents/skills.json` (`{"entries": [{"path": ".claude/skills"}]}`), write `~/.gemini/config/skills.json` (`{"entries": [{"path": "<RepoRoot>/.claude/skills"}]}`) in `00` and `02`, and stop copying skills into `~/.gemini/config/skills/` (retaining Claude/Codex sync in `02`).
- **Orca Hook Preservation:** When updating `~/.gemini/settings.json`, preserve official `~/.orca/agent-hooks/` hook entries while removing any custom/non-Orca hooks, and never alter `~/.gemini/config/hooks.json` Orca entries.
- **Native AGY MCP Config & Preflight:** In `02_runtimes_agy_orca_setup.ps1`, emit `codebase-memory-mcp`, `xerj`, `$RepoRootSlash/.venv/Scripts/python.exe` (`nautilus-engine`), and `$RepoRootSlash/.venv/Scripts/edgartools-mcp.exe` (`edgartools`) with dynamic `EDGAR_IDENTITY` propagation; update `scripts/preflight_resume.ps1` (`agy_native_mcp_config`) to accept `noesis` in either `command` or `args` and validate `~/.gemini/config/skills.json` when present.

### Precedence-Ordered AGY Context Load Manifest

1. **Workspace SSOT & Skills:** `AGENTS.md` (`46` lines) + `.agents/skills.json` -> `46/46` SHA-256-locked standalone skills in `.claude/skills/` (`UPSTREAM_SKILLS_LOCK.json`).
2. **Global Charter & Zero-Copy Skills:** `~/.gemini/GEMINI.md` (`5` lines, `8/8` cross-OS SHA-256 `057933bbda0db411bbfbc189c72a3e7b59f1989650e110f8591cf64728555c1c`) + `~/.gemini/config/skills.json` (zero-copy pointer to `Z:/noesis/.claude/skills` on Windows and `/mnt/z/noesis/.claude/skills` on WSL2).
3. **Native MCP Servers (`4`):** `codebase-memory`, `xerj`, `nautilus-engine`, `edgartools` declared in `~/.gemini/config/mcp_config.json` (zero `bash -c` wrappers, dynamic `EDGAR_IDENTITY`).
4. **Upstream Hooks Only:** Official Orca status hooks (`~/.orca/agent-hooks/*`) preserved exclusively; `hooks_zero = True` for all custom repository/runtime hooks.
5. **Minimal Plugin & Clean Env Hygiene:** `swarm` plugin only, `0` global workflows, and `0` leaked global API keys.

## Consequences

- **Positive:** Eliminates Disk-C skill duplication for AGY 2.0, preserves live Orca agent status hooks across Grand-Reset runs, resolves AGY MCP binaries directly inside `Z:\noesis\.venv` (and ext4 `~/noesis/.venv` on WSL2), gives operators native NTFS/Win32 speed as primary alongside a parity-locked Linux WSL2 Desktop (`2.35.2`) + `agy` CLI companion, and avoids PII leakage in tracked files.
- **Negative:** Requires Antigravity (`AGY 2.0`) to support `.agents/skills.json` / `~/.gemini/config/skills.json` directory-entry manifests, relies on `codebase-memory-mcp` / `xerj` being present on `PATH`, and WSL2 Linux Desktop GUI rendering depends on WSLg availability (while `agy` CLI operates headlessly without WSLg).

### Upstream Evidence & Empirical Benchmarks

- **AAIF & Antigravity Discovery:** `.agents/skills.json` and `~/.gemini/config/skills.json` point directly to the 46 SHA-256-locked skills in `.claude/skills/` (`UPSTREAM_SKILLS_LOCK.json`), verified `46/46` by `tests/test_architecture_manifest.py`.
- **Orca Hook Compatibility:** Official `~/.orca/agent-hooks/*.cmd` status hooks remain intact alongside `hooks_zero = True` for custom repo hooks (`LLM_HARNESS_MANIFEST.json` `official_upstream_orca_hooks_only: true`).
- **Grand-Reset & Preflight Verification:** Both `00_clean_disk_z_and_agy_reset.ps1` and `02_runtimes_agy_orca_setup.ps1` pass PowerShell AST parsing and `-DryRun`, while `scripts/preflight_resume.ps1` passes `13/13` always-on gates.

### Self-Invention Lesson Learned & Mechanical Upstream Gate

- **Lesson Learned:** Blindly deleting `"hooks"` and cloning 46 skill directories onto Disk-C treated symptoms instead of using native directory-pointer manifests and targeted hook filtering.
- **Mechanical Upstream Gates:** `tests/test_grand_reset_kit.py` (PowerShell AST + `-DryRun`, `.agents/skills.json` assertion, MADR 4.0 sections), `scripts/preflight_resume.ps1` (`agy_native_mcp_config`), and `gitleaks` (blocking any hardcoded personal `EDGAR_IDENTITY`).
